## The shape (concept + catalogue)
Owner's need: a two-person team (owner + Xenia) can't staff dedicated QA; owner finds
bugs ad hoc but can't catch them systematically. Wants a "not raw" version before F&F
testers (hand-picked first customers) touch it.

Decisions reached through the dialogue:
1. **Exploratory first** — find the sharp edges; harden the worst into automation later
   (regression suite parked as a "decide after we see findings" call).
2. **Sandbox = the whole dev project.** No separate staging (owner's call, simplicity).
   Wipe orders + photos at the aevia.at migration. Flagged: the wipe is really THREE
   wipes — Firestore docs, Auth accounts, and Storage files are separate systems; miss
   one and you get ghost logins / orphan files. Accounts can safely live.
3. **Staff/customer split is authorisation, not account type.** Owner spotted in the
   Firebase console that all logins share one Auth pool. Confirmed in code: the ONLY
   switch is the server-side `STAFF_EMAILS` allowlist (`functions/index.js:19`), no
   client-side copy, no `emailVerified` check for staff. So `claude-test@` becomes staff
   purely by being on that list — and gets full access to every order once deployed.
4. **Email testing** — auto-verify would bypass the email, so it can't check
   arrival/content. Adopted a **free-tier testmail.app inbox** (namespace `kidkd`):
   test accounts get API-readable addresses, so verification/confirmation/preview/
   referral emails are fetched + links followed fully automatically. Test inboxes
   can't judge real Gmail/Outlook spam or cross-client rendering → one manual owner
   eyeball per email type covers that.
5. **Photos** — synthetic images test the plumbing but can't verify visual correctness
   (does the book look right, do photos crop/place correctly). Owner provides real
   per-occasion libraries; Claude derives the broken cases (low-res, wrong-type,
   large-file) from them.
6. **Pacing is a dial the owner holds** — start gated (one case → owner checks token
   usage → go), widen to autonomous background batches once cost-per-finding proves out.
   Claude orchestrates via `orchestrating-work`, delegates test-running to
   `general-purpose` subagents (keeps the main thread lean; runs in background).
7. **Cost:** egress ≈ cents (uploads free; PDF renders in-region free per ADR-0006;
   verify via UI/status flags, not by downloading files; one deliberate large-file test).
   Tokens controlled by scripting + compact pass/fail + subagent delegation.
