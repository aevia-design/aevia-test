### `printsmarterPostback` deployed and verified end-to-end
**Done:** Deployed `--only functions:printsmarterPostback` (1st gen, europe-west1). The secret
already existed in `.env` from S155 (48 chars) — only the deploy was missing.
**Decided:** Register the URL with Printsmarter **by email**, and tell them their dev team does
**not** need to add a token or signature. S155 had asked them for one and got "I guess so, I'll
check with our DEV team" — that open loop is now closed from our side instead.
**Why:** The secret lives in the URL path, so a caller who does not know it gets a bare 404. That
is sufficient here: the URL only ever travels over TLS between their server and a Cloud Function,
never a browser. A request-body signature would be marginally stronger (URLs leak into logs and
proxies) — if their devs later offer one, add it as a second layer, but do not block on it.
**Verified** against the live endpoint, five cases:

| Case | Result |
|---|---|
| GET | `405 Method not allowed` |
| POST, wrong secret | `404 Not found` — no confirmation the endpoint exists |
| POST, no secret | `404 Not found` |
| POST, correct secret + unknown order | `404 Unknown order` — secret accepted, code running |
| POST, `http://` tracking_url | `400 refusing it` |

### Stripe address collection checked — already correct, no fix needed
**Done:** Read `functions/index.js:1055–1076`.
**Why:** The branch is on **whether a saved address exists**, not on whether the customer is
