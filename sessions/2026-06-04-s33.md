### 17:00 — Map wired into the book (3 surfaces)
**Done:** Replaced the `variant.mapCanvas` stub in `template-engine.html` (~line 2262)
and the mirror in `customer-preview.html` with the real region SVG + pins via shared
`map-render.js` (now `<script>`-included in both — it was only referenced in a comment
before). Added the map render to `scripts/export-pdf.js` `renderPage()`.
**Decided:** Read the FP1 selection from `window._wanderMap = {region, countries}`,
set from `order.fpTexts.fp1` in `loadOrderIntoEngine` (engine) / after `getOrder`
(customer) BEFORE `renderBook` so the map paints on first render (both fresh + restore).
PDF reads it from a new `state.mapSelection` field in book-state.json.
**Why:** `fpTexts.fp1` is an OBJECT `{region, countries, itinerary}`, not a string —
the render loop needed region+countries before painting the canvas.
**Watch out for:** Bleed-fit geometry differs per surface. Browser canvas origin =
CONTENT edge → map-render subtracts bleed (overlay 206mm, offset −3mm). PDF canvas
origin = BLEED edge (FULL_PX) → region SVG resizes straight to FULL_PX with NO
`expandSvgViewBox` (region SVGs are already bleed-framed, unlike content SVGs), and
pins use with-bleed coords directly (no subtraction). Don't "unify" these.
