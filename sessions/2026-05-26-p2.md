### — Caption xMm/yMm are CENTER coordinates, not top-left
**Done:** Discovered that all caption box coords in the CSV (spread and text panel) use center as the reference point, not top-left. Proven mathematically: FP3 `above (10mm from photo)` gives exactly 10mm gap when treated as center; 0mm gap if treated as top-left. Fixed in:
- `pages/template-engine.html`: `capLeft = (cap.xMm - BLEED_MM) * SCALE - capWidth/2`
- `scripts/export-pdf.js`: `textXPt = (capDef.xMm - capDef.wMm/2) * MM_TO_PT`; `textYPt = pageSizePt - (capDef.yMm + capDef.hMm/2) * MM_TO_PT`
**Watch out for:** The PDF y formula uses `yMm + hMm/2` (not minus) because pdf-lib y=0 is page bottom. Easy to get wrong. Same center convention applies to text panels.

### — Cover caption/slot coords: subtract 18mm bleed (not 3mm)
**Done:** Cover CSV coords include 18mm bleed. Engine was using `capDef.xMm * SCALE` directly → captions and photo slot shifted 54px (18mm) to the right. Added `COVER_BLEED_MM = 18` constant; engine now uses `(xMm - COVER_BLEED_MM) * SCALE` for cover photo slot and cover captions.
**Watch out for:** Never use the spread `BLEED_MM = 3` for cover calculations. They're defined separately in the engine and must stay that way. PDF export cover captions already used `cap.xMm * MM_TO_PT` (no bleed subtraction) — that was already correct because the cover canvas in pdf-lib is the full cover INCLUDING bleed. Do not add bleed subtraction to the PDF cover path.

### — Duplicate `const BLEED_MM` caused JS parse error → uploads broken
**Done:** Developer agent left two `const BLEED_MM = 3` declarations in the same scope (lines 1988 and 1993). `new Function()` parse error silently killed all JS — no uploads, no photo counter, no book render. Fixed by hoisting to a single module-level constant at line 806 alongside `SCALE`.
**Watch out for:** `const` in JS is block-scoped but if two declarations end up in the same function scope (e.g. both in a `forEach` callback), it's a parse error. Always define shared constants at module level.

### — display:flex on contenteditable breaks text-align
**Done:** Developer agent used `display:flex; flex-direction:column; justify-content` for valign on caption elements. This broke `text-align: center` — text appeared left-aligned even when `cap.halign = 'center'`. Fixed by removing flex and using `padding-top` approximation for valign instead. Since 23/26 captions are `valign: top`, padding-top is never applied for most captions.
**Watch out for:** Never use `display:flex` on `contenteditable` divs where text-align matters. Flex formatting context overrides inline text alignment in a way that's browser-inconsistent and hard to debug.
