### 1. Instruction-bar wrapping (point 1)
The frozen top instruction row was one long text run, so browser wrapping split phrases mid-sentence ("through your finished book" orphaned onto its own line). ### 2. Preview mode is now view-only (point 2)
Previously Preview still allowed repositioning photos (and, on inspection, slot-swap drag + caption edits too). Fixes, two layers:
- `window._previewMode` flag set in both mode-toggle handlers (`mode-edit-btn` → false, `mode-preview-btn` → true); crop-drag `pointerdown` now bails on it (mirrors the existing `_readOnly` guard).
- One scoped CSS rule: `.page-body.preview-mode #book-canvas [contenteditable], … .photo-slot { pointer-events: none; }` — disables swap-drag + caption editing too. Scoped to `#book-canvas` so the flip nav (prev/next/dots, which live outside it) stays clickable. Reversible for free — auto-restores on return to Edit; no per-element JS teardown.

### 3. Special-photo drag question (point 3) — PARKED, not built
Owner asked why cover/special-page photos can't be dragged back to the sidebar like pool photos when we already let them be repositioned. Reviewed the code: the lock is intentional — special photos are chosen at order time, bound to a required slot (`book-completeness` guard), so "drag to sidebar" has no valid empty end-state, and the lock stops a customer accidentally emptying a required frame before approving. Repositioning (✥) already covers the real "it's off-centre" need. Owner reflected he tends to over-perfect the MVP from day 0; agreed to do nothing. Parked in `ideas.md` as "Replace special-page photos … build only if a real customer asks during the F&F trial."
