## Key decisions / learnings
- **Grey backdrop belongs at the compositor, not the web layer.** First attempt recoloured the web webp with a neutral-light mask → left white-line artifacts. Correct fix = bake grey in `compose-mockup` (`BG_R/G/B`). All 5 orders' raw captures (`sessions/qa-runs/spread-*`, `cover-wrap-*`, manifests) are present locally, so regeneration is fully local — no re-capture, no staff password, no GCS egress.
- **Shadow "heavy/straight/rectangle" bugs were all CROP artifacts**, not generation. The book sits large with a long soft shadow below; cropping tight or asymmetrically clipped the shadow mid-falloff (straight edge) or unbalanced it (book high, shadow blob low). Fix = crop **symmetrically around the book, including the full shadow falloff to the image bottom** → book centred, shadow fades naturally. Spread crop landed ~4:3 so it fills the hero.
- **Covers are already centred** in the source (my early "off-centre" was a loose bbox including the shadow). Cover crop 4:3, centred.
- **Hero can't perfectly fit both** a square cover and wide (2-page) spreads with one aspect. 4:3 balances; 5:4 favours the cover. **Owner deferred the 4:3-vs-5:4 call** (needs to see both with Kseniia) — page left on 4:3; `front54.webp` + injected CSS used to produce the 5:4 comparison shots.
- **Design review** (`/design-review`, design-review agent) verdict = *approved with fixes*; all high-priority items applied (width 1160→1400, hero scale, front cover as thumbnail #1).
- Front cover is **thumbnail #1 and the default hero** (reselectable) — AU pattern. 11 thumbs → tidy 6+5 (row1 covers+spreads, row2 specials).
- Thumbnails + right-card thumbs use **padding + object-fit:contain** so images don't touch cell edges.
- **Arrows + keyboard nav**: prev/next buttons on the hero; ArrowLeft/Right cycle images on the page AND in the full-screen lightbox (lightbox stays in sync).
