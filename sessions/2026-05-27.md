### — Order form photo grid: sequential queue + incremental DOM
**Done:** Rewrote `handleMainFiles` as a sequential async queue (`drainUploadQueue` / `processAndAddFile`). Replaced `renderPhotoGrid` full-rebuild pattern with `appendPhotoThumb` (append one thumb) + `refreshThumbBadge` (patch badge only). Full rebuild (`rebuildPhotoGrid`) now only called on remove.
**Decided:** Sequential processing, not parallel — matches template engine pattern exactly.
**Why:** Old approach fired 30 parallel async res-checkers, each calling `grid.innerHTML = ''` + full rebuild. For 30 photos: ~465 img decodes cascading. The browser flushed all deferred paint on alt-tab return, causing a 5–10s stall. Template engine avoids this by processing one file at a time and appending incrementally.
**Watch out for:** `_objUrl` is now created synchronously (before `mainFiles.push`) for JPEG/PNG, so the thumb always shows the image on first paint. Do not move URL creation back into `renderPhotoGrid` — that was the original cause of the stall.
