### 2. chunk-024 PDF generation — three layers of failure, root-caused via /systematic-debugging
Evidence pulled from actual Cloud logs (function + Cloud Run). Note: **logs are UTC; Evgeny is CEST (+2)**.
1. **PERMISSION_DENIED** — Cloud Run's Compute default SA (`677807969667-compute@developer.gserviceaccount.com`) had no Firestore/GCS access. Granted `roles/datastore.user` + `roles/storage.objectCreator` (it already had `storage.objectViewer`).
2. **`Cannot read properties of null (reading 'size')`** — `console.log(...gcsUrlByName.size...)` in `export-pdf.js` (~line 1127) threw in server mode because `gcsUrlByName` is null when `photoBufferMap` is set. Gated the log on `photoBufferMap` first.
3. **THE REAL ONE — 300s function timeout.** Logs proved the render *works* (AEV-043: started 14:52 UTC, finished + uploaded 14:59 UTC = ~6m43s) but `generatePdf` was synchronously awaiting it and died at its 300s cap. Browser saw "Failed to fetch"; the PDF was actually sitting in GCS. Synchronous-wait can't survive a multi-minute job (an 80-page book ≈ 13 min, and gen-1 functions cap at 540s).

### The fix — async render + Firestore-polled progress bar (also delivers Evgeny's progress-bar request)
- `scripts/export-pdf.js` — added optional `progressCb` to `generatePdfFromFirestore`, fired once per spread. CLI path untouched.
- `services/pdf-renderer/index.js` — renders **inside the request** (CPU billed only while working → no idle billing), writes `pdfRender:{status,done,total,pageCount,sizeBytes,gcsPath}` to Firestore at start / throttled during / on done / on error.
- `functions/index.js` — `generatePdf` is now a thin trigger: fires Cloud Run without awaiting, polls Firestore until `status='rendering'` (confirms start, absorbs cold start), returns 202 in seconds (timeout dropped 300→60s). New **`getPdfStatus`** function returns progress and signs the preview URL when done.
- `pages/staff/dashboard.html` — replaced frozen "Generating…" with a live **progress bar** ("Rendering… N%") polling `getPdfStatus` every 2.5s, then shows Preview PDF link + size.
- **Cost decision (Evgeny asked):** CPU is cost-neutral for CPU-bound jobs (vCPU-seconds), so bumped Cloud Run to `--cpu 4` (~2× faster, ~same $). Avoided `--no-cpu-throttling` (the real idle-billing trap). See LEARNINGS.
