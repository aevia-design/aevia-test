## 1. Wander SP5 overlay — the S144 CSV sync was inert

Owner reported SP5 right still rendered art *above* the photos despite `overlay_position=below` in the CSV.

**Root cause:** S144 wrote `overlayAbovePhotos: false` on the SP5 right **page variants**. That is the *spread-level* key written at page level. Every reader checks `spreadDef.overlayAbovePhotos === false || variant.overlayBelow`, so it matched neither branch and was silently inert — in the engine, customer-preview **and** the PDF. Joyride and Tender already use `overlayBelow: true` on the variant; Wander was the lone outlier.

**Fix:** two lines, `overlayAbovePhotos: false` → `overlayBelow: true`. No engine code changed.

**Verified in the rendered DOM**, not the data file: every SP5 right overlay computes `z-index:0`, all 37 others stay `2`. Added `tests/overlay-z-order.test.js` — fails if `overlayAbovePhotos` appears on any object carrying an `svg`. It went red naming both lines before the fix. See LEARNINGS 2026-07-21.

⚠ The **V variant** was never seen rendering (fixture photos are landscape). Covered by the unit test; the data change is symmetric.

## 2. Print PDFs from the dashboard

Migrated print mode from CLI-only to the Cloud Run renderer. New **"Generate print PDFs"** button; **owner confirmed it works.**

Output is **two** files, never one:
- `{order}_print_cover.pdf` — wide wrap (back|spine|front)
- `{order}_print_inside.pdf` — square single pages, blank QR page last

**Decisions (via `/solutioning`):**
- **Two documents, not one.** Cover and interior are different page sizes; print houses reject mixed-size PDFs. The pre-existing CLI merge lumped them together — that was the real defect, not "one PDF per spread" as first thought (the CLI already merged in `--order` mode).
- **Single pages, not reader spreads.** The print house does the imposition, and no Aevia artwork crosses the gutter (each page has its own SVG + bleed). Owner corroborated: the first physical samples were printed from single pages. Reversible if Elanders disagree (~20 lines).
- **RGB stays.** Elanders convert to CMYK themselves — settled S119, `docs/briefs/print-api-integration.md` §4. A stale memory claimed this was still open; corrected.
- **Spine stays 9mm** — correct for the 40pp samples being printed now. Wrong for 80pp (their Q1).

Changes: `pdfMode` threaded through `generatePdfFromFirestore`; server print mode accumulates pages in memory and returns `{coverBytes, insideBytes, pageCount}`; renderer uploads both and records both paths in `pdfRender`; `getPdfStatus` signs both; `getPdfUrl` accepts `print_cover`/`print_inside` (path is `{order}_{type}.pdf`, so the type *is* the suffix). CLI behaviour unchanged.

Caught during the build: `updatePdfLinks` rebuilds the whole action row, so the new button vanished as soon as any PDF existed. It is now re-offered there too.
