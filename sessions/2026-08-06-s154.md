**Decided:** `checkPageCountAgainstSequence()` throws in PRINT mode, warns and records

**Why:** The cover spine is sized from `pageCount` but the interior comes from the built

### 14:10 — 'bold' as a string printed regular
**Done:** Papercut's weights → numeric 700/400; `normaliseWeight()` maps CSS keywords to
numbers before the style ladder in `coverCaptionStyle` and the three override paths.
**Why:** `coverCaptionStyle` picks the font cut numerically and `'bold' >= 700` is false —
the string coerces to NaN, every branch falls through to `'regular'`, and the PDF drew
SourceSans3-Regular. Both engines rendered bold anyway because `font-weight: bold` is valid
CSS, so screen and print disagreed with no error. The bold font file was registered and
present the whole time.
**Watch out for:** Papercut was the only template affected, but Xenia's CSVs name fonts as
"Source Sans 3 **Bold**", so the word is what gets copied into a data file. A test now
asserts no template declares weight as a string; verified it fails when one is reintroduced.

### 15:00 — Customer "Save changes" does not reach the PDF (by design)
**Decided:** No change. Confirmed the intended contract.
**Why:** Customer saves write `customerCaptions` etc. via `saveOrderState`; `approveOrder`
copies `customer*` → `staff*`; the renderer reads ONLY `staffBook*`. So edits are a draft
until Approve promotes them. Correct for print, which happens after approve + pay.
**Watch out for:** The promotion is a blind overwrite with no merge and no staleness check.
If a customer saves, then staff save in the engine, then the customer approves, the
customer's older snapshot silently discards the staff work — and vice versa. Nothing
compares `customerUpdatedAt` against the last staff save. Two proposals not yet built:
show staff that unapproved customer edits exist before they Generate PDF, and warn on the
collision at approval time.
