## Feature #1 — original photo filenames (Option B)

Staff now see each pool photo by the customer's **original filename**; the chronological
sort fallback uses those numbers. Customer side **hides** filenames. The internal key
(`photo_NNN`) is untouched → save/load keying carries zero risk.

- **`functions/upload.js`** — added `photoManifest.poolOriginalNames[]`, parallel to
  `pool[]` (same order/length). The original name was already captured (`u.originalName`),
  just discarded before — now persisted.
- **`functions/index.js`** — `getOrder` returns `storedNames.poolOriginalNames`.
- **`assets/js/photo-utils.js`** — `comparePhotos` filename-number fallback reads
  `displayName || name` (the one central sort change; both engine sort sites flow through it).
- **`pages/staff/template-engine.html`** — `processOneFile` returns `displayName`
  (defaults to `file.name`, already the original for local uploads); on order load
  `displayName` is set from `poolOriginalNames[i]`; replaced the duplicated inline sort
  with `comparePhotos`; sidebar thumb label/title/alt + sort-method logs use `displayName`.
- **`pages/customer-preview.html`** — `.thumb-name { display:none }` (hides internal names).
- **`tests/photo-utils.test.js`** — +2 tests (displayName override + legacy fallback).

**Key design choice (low risk):** `markDuplicates` and `assignmentsToNames` still key on
`.name` (stable `photo_NNN`). Original names can collide or be missing; the internal key
can't. So `displayName` is purely display + sort metadata, re-derived from the manifest
on each load (not persisted in saved book state).

**Legacy orders** have no `poolOriginalNames` → fall back to `photo_NNN`. No migration.
Real `IMG_xxxx` names appear only on the **next fresh upload** — not yet seen in browser.

## Feature #2 — approve→pay flow fix

All four researched changes (Baymard et al., S29 notes). `pages/customer-preview.html`
+ one field surfaced in `functions/index.js`.

- **(a)** Review → Approve → Pay progress cue in the action bar (`.flow-steps`, driven by

- **(b)** Forward post-approve copy: *"✓ Design approved & locked — one last step:
  complete payment to send your book to print."* (was terminal "we'll be in touch").
  Now `var(--text)`, reads as an active prompt.
- **(c)** "We'll be in touch" now lives **only** in the post-payment notice.
- **(d)** Pay button shows the order price: `Pay now · €70`. `getOrder` now returns
  `price` (already stored at order time in `upload.js:282`, just wasn't surfaced).

**⚠ Watch-out (cost source-of-truth split):** the Pay button shows the **order-time

(`index.js:511`) — a separate number. They match today (both €70 on test orders). If you
ever change the Stripe price, old orders' button would show the old price. Either accept
(shows what they agreed to) or unify later.
