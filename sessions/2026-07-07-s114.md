### 2. New `issue` side-state + report channel
- `customer-preview.html`: a "Report an issue" link in the action bar → small modal
  (textarea) → POST to new `reportOrderIssue` Cloud Fn.
- `functions/index.js` `reportOrderIssue` (token-gated via `previewToken`): saves
  `issueNote` + `issueReportedAt`; flips status to `issue` ONLY when current status
  is `review_sent` (never clobbers approved/paid); pushes `statusHistory`; emails
  `support@aevia.at` (from `orders@`, replyTo the customer) with order#, customer,
  status, and the message. Email failure is caught and logged so the note still

  red-tinted `tr.row-issue` with an inline ⚠ `issueNote`, an **Issues** filter
  (replacing the two removed ones), the repurposed **Issues** stat card, and a
  stable sort floating issue orders to the top of the visible list.
- Customer-facing: `issue → "Under review"`.

## Full status flow now
```
uploading → new → review_sent → approved → paid → sent_to_print → printing → in_delivery → delivered
                       ↑ ↓
                    (issue)   ← side-state
```
Auto transitions: `uploading→new` (confirmUpload), `review_sent→issue` (reportOrderIssue,
only from review_sent), `review_sent→approved` (approveOrder), `approved→paid` (Stripe
webhook). Manual: `new→review_sent` (Send preview), `issue→review_sent` (Resend preview),
`paid→sent_to_print` onward (staff dropdown). Everything past `paid` is the unbuilt
print-hub API track.
