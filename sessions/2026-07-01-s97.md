## The ask (owner, refined over two review passes)
The book's left edge read as a flat side shadow / thin coloured strip. Papercut's spine "looked blue/grey and barely visible." Owner wanted, consistently for ALL front mockups:
**visible side spine → soft darker recessed groove → subtle highlight/transition → flat front cover** — gradient-based, no hard vertical line, slightly stronger so it reads at web scale but still natural. Constraint: change ONLY the left edge — not camera, composition, book size, proportions, cover design, photo, or text. Owner asked whether this could be read from the layered PSD automatically, or which layers to add.

## Investigation (answered the automation question)
- Inspected `assets/mockup example/new/{front,back}.psd` layer structure + pixel-probed the fold.
- **Root cause of "blue/grey spine":** the script hardcoded a `SPINE_COLORS` table with papercut = `#8bb8d8` (≈ its own cover colour → invisible). The **correct** per-template spine colour already lives in the engine cover-wrap's centre strip (`[back|spine|front]`): papercut = mint `121,186,155`, newborn `192,213,238`, etc. So the table was both unnecessary and wrong.
- **Groove:** the PSD's `Layer 1` (multiply) bakes only a ~1px hinge shadow that vanishes on light covers. The fold is genuinely narrow (measured: book edge x935, spine x935–939 = 5px, cover from x940, perfectly vertical + constant across all rows).
- **Conclusion:** no PSD changes needed. Spine colour = auto from wrap; groove = synthesize in code as scene-fixed geometry (owner chose synthesize-in-code over a Xenia PSD round-trip; wanted it generalizable + a guaranteed way back).

## What changed — `scripts/compose-flat-mockup.mjs` (front view only)
1. **Deleted `SPINE_COLORS`.** Added `sampleSpineColor()` — averages a ±6px box at 0.50×0.50 of the cover-wrap → the template's real spine colour, passed into `composeSide`.
2. **Rebuilt the left edge (Step 3):**
   - Spine face x935–939: recolour the preserved newborn sliver to the sampled colour, scaled by each pixel's luminance (keeps baked 3D highlight).
   - Hinge joint (Step 3b): a Gaussian **shadow valley** (centre x943.5, w3.6, depth 0.26) + Gaussian **highlight** (centre x952, w4.0, amp 0.08), multiplied onto the cover. Template-independent, gradient-based. Verified papercut luminance: spine 164 → groove trough 139 → highlight peak 199 → flat cover 175.
   - Gotcha fixed mid-session: `Math.exp(-((x-c)/w)**2)` is a JS syntax error (unary before `**`); needs extra parens.
3. Step 2 (face swap + Layer 1/Highlight) and Step 2b (bottom-edge bevel) unchanged. Back view unchanged (face-swap only).
