### 12:50 — Bug: map page never entered the book sequence
**Done:** Order-only functional pages (Wander FP1, `mapPage:true`) are now injected
into the book. `loadOrderIntoEngine` captures them from `order.fpSelections` into
`window._orderOnlyFPs`; `renderBook` prepends them to `selectedFPs`; cleared on
Local-mode switch + template change. (`template-engine.html`.)
**Decided:** Separate `_orderOnlyFPs` global rather than a fake checkbox.
**Why:** `buildLocalTemplateUI` deliberately EXCLUDES `mapPage` spreads from the FP
checkboxes (L3497-98 `functional && !s.mapPage`), but the sequence was built purely
from `:checked` boxes → the map page could never enter → it got replaced by a
standard photo spread (and photos came up short). The S33 headless test missed this
because it force-injected `_restoreState.sequence=['FP1']`, bypassing the checkbox path.
**Watch out for:** Any future order-only page (no checkbox) needs the same injection.
`_orderOnlyFPs` must be cleared when leaving Order mode or it leaks into Local renders.

### 13:10 — Scroll perf: full-res thumbnails (pre-existing, not a regression)
**Done:** Added `loading="lazy"` + `decoding="async"` to the photo-strip `<img>` in
BOTH `template-engine.html` (~L1487) and `customer-preview.html` (~L1547).
**Decided:** Lazy/async (timing only) over downscaling (touches pixels). No quality change.
**Why:** Engine sidebar renders FULL-RES object URLs as thumbnails — always has;

**Watch out for:** Heavier fix (downscaled display thumbnails, S18 pattern) is the
fallback if lazy-load isn't enough. Don't swap the upload to a downscaled copy.

### 13:40 — Map frame asymmetry = SVG artwork, NOT our render
**Done:** Proved (pixel measurement, new `qa/measure-map-frame.mjs`) the EU map SVG's
brown frame band is 2.7mm left / 5.3mm right, 4.3mm top / 5.0mm bottom — asymmetric
BEFORE any clip. Our clip math is provably symmetric (618px map, −9px offset, 600px
canvas → clips exactly 9px/3mm each side).
**Decided:** Root cause = the S25→S32 bleed expansion. S25 viewBox was `0 0 566.93 566.93`
(200mm, content-only square); S32 became `0 0 583.937 584.105` (206mm, +3mm bleed) but
anchored TOP-LEFT at (0,0) instead of centred → all extra bleed piled on right+bottom.
**Why:** Evgeny recalled manually editing the viewBox in a prior session — confirmed by git.
**Watch out for:** This is in the SVG, fixable only by re-export (or per-file viewBox
surgery — fragile across 6 region maps). Re-export handed to Kseniia.

### 14:00 — Decision: switch region maps SVG → PNG
**Decided:** Re-export region maps as **centred PNG, 600 DPI, even 3mm bleed baked in**
(206mm = 4866px @600dpi / 2433px @300dpi), not SVG. Handed to Kseniia alongside the
re-centre fix.
**Why:** `export-pdf.js` already rasterises everything to 300 DPI PNG via Sharp — so
SVG's vector-sharpness advantage NEVER survives to print. PNG renders pixel-identically
in browser (preview) AND Sharp (PDF), killing an engine-parity class of bug; geometry
becomes trivial pixels (the thing that bit us today); lighter/faster than the 8MB SVGs.
**Watch out for:** When PNGs arrive, swap the map source `.svg`→`.png` in 3 places
(engine, customer-preview, export-pdf.js) + verify each with `qa/measure-map-frame.mjs`.
Code change NOT yet done — waiting on Kseniia's export.
