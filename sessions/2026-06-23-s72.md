## 3. EU storage migration (commit `8f5171d`, ADR-0006) — the big one
Investigating a €0.37 / 3.63 GiB egress charge on 22.06 revealed the root cause: **the photo bucket was in `US-WEST1` while everything else (Firestore `europe-west3`, Functions + Cloud Run `europe-west1`) is in the EU.** So each server-side PDF dragged ~1 GiB of originals across the Atlantic, and customer photos sat split from their metadata. (AEV-043 *did* have derivatives — web-res was working; the 3.63 GiB was the 2 cross-region PDF renders.)

Decision (ADR-0006): create EU bucket now, while data is throwaway test orders — the cheapest possible moment for a one-way door. Executed + verified:
- Created `gs://aevia-uploads-eu` (`europe-west1`), granted the renderer SA objectAdmin.
- `rsync`-copied all 9.22 GiB US→EU (byte-identical).
- Repointed all 6 server-side files; **re-bound the `generateDerivative` storage trigger** from the default bucket to the EU bucket — the key gotcha — and **verified it fires** (24.4 MiB original → 263 KiB preview).
- Redeployed 17 functions + the Cloud Run renderer (rev 00004).
- Old US bucket retained as fallback (untouched, not deleted).

Result: **full EU data residency** + chunk-024's in-region PDF read finally lands (free).
