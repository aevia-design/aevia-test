### Closed-book mockup — perspective warp DONE
The S56 blocker was the tilted cover face skewing under a rectangular `fit:'fill'`. Solved with a real 4-corner homography in `scripts/compose-closed.mjs`:
- **No smart-object transform available** — the PSD places the cover via a Photoshop smart object whose perspective transform `ag-psd` does NOT expose (`placedLayer` undefined). So we supply the warp ourselves.
- **Homography** — `solveHomography()` (8×8 Gaussian elimination) maps the flat front-cover art → the cover top-face quad; rendered by inverse-sampling each output pixel (bilinear). Verified pixel-exact by warping the PSD's OWN example cover and comparing to Photoshop's baked composite — identical.
- **Top-face quad (calibrated constant)** — `q = {top:[1641,361], right:[2465,1086], bot:[1104,1620], left:[410,754]}`. Detected from the cream example design baked in `psd.canvas`. CRITICAL: the book's OUTER silhouette ("Book" layer extremes) includes ~70px of cover-board thickness hanging below the near edge; mapping art to the silhouette spilled navy onto the page block. The true top face is ~70px higher at BOT. PSD geometry is FIXED and shared across all templates (only the wrap changes), so the quad is a constant.
- **Corner correspondence** — `ROT=3` (env-overridable) rotates the art→quad assignment so the design lands upright (photo up, title below, spine to the left). Chosen by rendering all 4 rotations and eyeballing.
- **Channel bug fixed** — the wrap PNG is RGB; sampled it as RGBA (`*4` stride) → grey garbage. `.ensureAlpha()` on the source buffer fixed it.
- **Black spine fixed** — the board edge was multiplied near-black by "Edge copy"; softened to `withOpacity(..., 0.45)` so it reads as cover navy.

### Bleed clarified (Evgeny's question — answered, no code change)
- **Cover wrap bleed = 18mm/side** (`COVER_BLEED_MM=18` in engine/customer/PDF) — the hardcover **wrap/turn-in**, folds around the board, NEVER on the finished face. Distinct from the **3mm interior-spread content bleed** (`newborn-data.js bleed:3`).
- **Engine `.cover-canvas` + `cover-wrap-newborn.png` = TRIM** (409×200mm, back 200 | spine 9 | front 200, NO bleed). Coords are with-bleed but the render subtracts 18mm.
- **PDF = trim + 18mm bleed all around** (445×236mm).
- **Conclusion:** the mockup uses the trim = the correct finished-book view. The "elements off vs the PDF" Evgeny saw is mostly the 18mm (9%/side) bleed framing difference — apples-to-oranges, NOT a mockup bug. The engine render == the mockup outcome. Earlier "stale capture" guess was likely wrong. (Any CENTER-of-cover difference, e.g. a butterfly on the man's face, would be a separate engine-vs-PDF decoration-parity question.)
