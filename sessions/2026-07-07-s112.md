### Commit `75b423a` — pdf-renderer: fix hang on large photo sets
- **`services/pdf-renderer/index.js` `fetchAllPhotos`** rewritten from an unbounded `Promise.all` over the whole pool to a **6-worker bounded-concurrency pool**, plus a **per-photo download timeout** (120s) that rethrows so a stalled stream becomes a fast named error (`pdfRender.status=error`) instead of a 15-min silent stall. Deployed by owner via `gcloud run deploy aevia-pdf-renderer --source … --memory 8Gi --cpu 4 --timeout 900`. AEV-051 preview PDF then generated successfully.

## Root causes (from Cloud Run logs)
- **AEV-050 → instant cover-only PDF:** the `generatePdf` guard wasn't deployed yet (owner had pushed frontend to Cloudflare but not run `firebase deploy`). Renderer log: `Template: Tender, 0 spreads` → cover only → done. 0 spreads = book never saved. Guard now deployed.
- **AEV-051 → stall at 0%:** renderer log stopped at `Template: Wander, 20 spreads` before `Fetched … photos`; `/generate` requests returned **504 after exactly 900.000s** (Cloud Run kill), 3 attempts. Cause: `fetchAllPhotos` downloaded the **entire photo set in parallel**. AEV-051's originals are large pro-camera shots (~20 MB avg, up to 66 MB); pulling them all at once stalled the streams. Bounded concurrency fixed it.
