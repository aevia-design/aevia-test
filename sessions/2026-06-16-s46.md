## Bug traced + fixed this session (uncommitted) — order-form over-upload
- **Symptom:** 40pp Newborn + Intro + Labour asked for 51 main photos; uploaded ~53; submitted fine; staff engine showed **2 unplaced** though all slots filled.
- **Root cause (via /systematic-debugging):** NOT a counting bug — `calcPhotoTarget` correctly returns 51 = engine's regular-slot count (Newborn H/V variants have matching slot counts, so orientation can't shift it). The submit validation only enforced the **lower** bound (`uploaded < required`, order.html); over-upload was silently accepted, so the engine filled its exact 51 slots and left 2 surplus pool photos unplaced.
- **Fix (option (a), Evgeny's call):** block when `uploaded !== required` (both ends). Message on over: "Please remove N photos — your book has 51 photo slots…". Shared `order.html` → fixes ALL templates. Regression test added; **102/102 tests** (was 97).
- **Note:** the already-submitted test order still has the 2 extras in its pool (expected — client-side guard only); delete 2 in-engine or ignore.
