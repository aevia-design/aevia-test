## 2. Explained the Codespace working model (owner is new to this)
Spent time on the mental model, since the owner moved off his local laptop:
- **Template folders** live at `assets/Template_<Name>/` (one folder per template, with a `Spreads/` subfolder inside for SVG artwork). Same location as before — just on the cloud machine's disk now.
- **git is the sync mechanism.** GitHub = the permanent hub; Codespace + laptop are working copies. When the laptop returns from repair, one `git pull` brings down exactly what changed — no manual file-picking. Only secrets (`functions/.env` etc.) don't travel via git; the laptop already has its own copies.
- **The Codespace is disposable** (~30 days idle → auto-delete). Nothing is safe until committed + pushed.
- **Editing files in the Codespace:** drag-drop into the VS Code explorer to add Xenia's SVGs/CSVs; no more Excel-on-local-disk.
- **Opening CSVs tabular:** install **Rainbow CSV** (colour + hover-header; set separator to `;` since these files are semicolon-delimited) or **Edit CSV** (true Excel-style grid). No download needed.
- **Local dev over port forwarding:** `npx serve . -p 8080` runs *inside* the Codespace; reach it via the forwarded URL from the **Ports** tab (globe icon), not `localhost`. If the "getting your codespace ready" screen hangs, open from the Ports tab or set the port to Public temporarily.
