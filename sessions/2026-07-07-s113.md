## Key decisions (shaping dialogue)
- **Use Stripe native Coupons/Promotion Codes, not a custom promo store** — Stripe enforces
  every abuse mode the owner worried about (expiry, `max_redemptions`, per-customer caps,
  first-order-only, no stacking) server-side.
- **F&F = shared code, capped by BOTH count (50) AND date (Aug 31).** Owner fine with a
  shared code; low cap + short window contains the only real risk (public leak).
- **Referral eligibility:** referrer must be a **verified account holder** (needs a home for
  their code + reward); **referee needs no account** — redeems at guest checkout. Nudges
  account creation without blocking guests. Fits ADR-0007 (optional accounts).
- **Referral reward = one €10 code per referral, NOT an accumulating wallet.** Stripe allows
  only one promo code per checkout, so two referrals = two €10 codes used on two separate
  orders (not €20 on one). Deliberate: avoids a self-managed credit ledger. A true
  accumulating balance (`referralCreditCents` + dynamic coupon at checkout) is a separate
  future build if ever wanted.
- **Both referrer and referee get €10** (referee on first order; referrer on next order,
  only after the referred order is **paid**).

## Side question answered (payment methods)
"Direct Visa/Mastercard for lower fees" premise is off — a processor like Stripe is always the
thing talking to the card networks; you can't take cards without one. The real lower-fee lever
in Austria/DACH is adding **SEPA / EPS / bank methods** (Stripe supports these — config, not a
new provider). Parked as a separate future thread, not written up.
