### PDF renderer fixes (`scripts/export-pdf.js`) — Stage 7
Driven by a real "rendered as Scribble" bug, then `/systematic-debugging` on a 95% stall:
1. **Silent Scribble fallback removed** — `setActiveTemplate()` THROWS on an unknown-but-specified
   template. Root cause: the **Cloud Run renderer is a separate deploy** from the website; a stale
   container didn't know Tender → fell back to Scribble. Fix it loud so deploy-skew is obvious.
2. **OOM, not timeout** — preview embeds full-res lossless PNG pages (~177 MB); 4 GiB OOM-killed at
   page 38/40 (progress froze at 95%; log showed render → fresh `listening on port 8080` = restart,
   at ~3.5 min « 900s cap). Fix: redeploy `--memory 8Gi` (cost ≈ +$0.002/render).
3. **Spine caption off-band** — pdf-lib `heightAtSize()` returns **inverted** ascent/descent for
   Parisienne (asc 8.05 / desc 16.47). Diagnosed by measuring browser `measureText` + fontkit +
   pdf-lib side by side (after burning time reasoning from font math that kept "proving" they
   matched — reinforces inspect-render-first). Fix: read ascent/descent from `font.embedder.font`
   (fontkit); identical value for the other 4 spine fonts → shipped templates unchanged.
4. **SVG raster cache** (`svgRasterCache`) — a book reuses ~7 spread designs; the decorative SVG
   rasterised every page. Memoise by path|FULL_PX, cleared between requests. Modest win (corrected
   my over-claim: the slow pages — e.g. SP5 — are slow from **2 photo slots**, not the SVG; the
   5.7 MB files are SP Spread 1 and render fast). Not yet measured live.
