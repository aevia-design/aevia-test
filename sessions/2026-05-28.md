## Session 2026-05-28 — SVG bleed fix + PDF polish

### — SVG bleed fix in export-pdf.js — DONE
**Done:** Spread and cover SVGs are now rendered with their viewBox expanded by the bleed
amount before passing to sharp. New helper `expandSvgViewBox(svgStr, bleedUnits)` does a
regex replace on the viewBox attribute (e.g. `0 0 566.93 566.93` → `-8.504 -8.504 583.938 583.938`
for spreads; 51.024 units for cover). Constants: `SPREAD_SVG_BLEED_UNITS` (~8.504) near
spread constants, `COVER_SVG_BLEED_UNITS` (~51.024) near cover constants.
Cover compositing also changed: canvas bg = front colour (not back), spineRect + frontRect
removed, photo composited BEFORE SVG (SVG draws back+spine bleed on top).
**Watch out for:** Spread SVG viewBoxes are `0 0 566.93 566.93`. Cover is `0 0 1159.37 566.93`.
If Kseniia re-exports with different viewBox dimensions the constants stay correct (they're
derived from BLEED_MM * 72/25.4 — the expansion is always correct regardless of base viewBox size).

### — Blank QR page appended to PDF — DONE
**Done:** After all content pages, one blank white square page (PAGE_SIZE_PT × PAGE_SIZE_PT)
is added in both preview and print modes. Print mode writes it as `page-XXX.pdf`. Preview
mode adds it to the combined PDF. Required by print house for their QR code placement.
Applies to both 40-page and 80-page books.

### — Full-bleed photo support — DONE
**Done:** New `full_bleed` column in `Scribble_sizing_full.csv` (yes/no). `csv-to-template.js`
reads it and emits `fullBleed: true` on the slot. Currently one page marked: FP2 right page
(photo exactly matching 206×206mm with bleed).
PDF `renderPage`: if `slot.fullBleed`, resize photo to `FULL_PX × FULL_PX`, place at `(0,0)`.
Engine: if `slotDef.fullBleed`, same as `heartClip` — slot fills 600×600px at `(0,0)`.
`scribble-data.js` regenerated.
**Watch out for:** Full-bleed slot in the data has `w=200, h=200` in the CSV (content area
dimensions) and `fullBleed: true`. The actual output is FULL_PX (206mm) because the code
explicitly overrides size/position when the flag is present.

### — Text panel word wrap fixed in PDF — DONE
**Done:** FP text panels (FP1 birthday wishes, FP4 captions, etc.) were not word-wrapping
in the PDF — text rendered as one long overflowing line. Root cause: slot captions used
`wrapText()` but text panels only split on `\n`. Fixed by applying `wrapText()` to text
panel lines too (line 473 in export-pdf.js). FunnyWords panels unaffected (short words per line).

### — Caption position audit — no bug found
**Done:** Full audit of all spread captions — engine uses `(xMm - BLEED_MM) * SCALE` and
PDF uses `xMm * MM_TO_PT` on a 206mm page. Both produce identical content-area positions.
Zero mismatches found. Earlier visual "misalignment" was likely SVG artwork being stretched
(before today's bleed fix) making decorations appear offset relative to captions.
