**Why:** Rules only permitted `status` and `statusHistory` — `generatePreviewLink` was writing `previewToken`, which was silently blocked with "missing or insufficient permissions".
**Watch out for:** If any other new field needs to be written from the dashboard browser client (not Cloud Functions), it must be added to the `hasOnly([...])` allowlist in `firestore.rules` and redeployed.

### GCS photo loading parallelized
**Done:** `loadOrderIntoEngine` in `template-engine.html` now fetches all pool photos via `Promise.all` in parallel, then processes sequentially (HEIC WASM constraint unchanged). Special/cover photos also fetched in parallel batch. Progress counter shows "Downloading X / N" then "Processing X / N".
**Why:** Previously 40 sequential fetch+process calls. Fetches are pure network and have no shared state — parallelising them cuts total download time from `N × single_fetch` to ~`1 × single_fetch`.
**Watch out for:** Processing remains sequential — do not parallelise `processOneFile`. HEIC WASM module has shared internal state and corrupts output if called concurrently.
