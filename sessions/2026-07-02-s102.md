## Key decisions made

- **Split human mail from robot mail.** Microsoft 365 (Xenia's existing paid mailbox +
  free aliases) for mail humans read; **Brevo** for all automated app-sent mail.
  Reason: Microsoft is deprecating SMTP-AUTH basic auth (partial rejection starts
  **March 1, 2026**, ramping to 100% by **April 30, 2026**) — building automated
  sending on that path now would break within months. Verified against Microsoft
  Learn, not just secondary sources.
- **Brevo chosen** for its free tier (300/day ≈ 9,000/month, far above current
  volume), EU hosting/GDPR, and established reputation (formerly Sendinblue,
  publicly traded, 600k+ customers) — verified, not just cost-picked.
- **Single mailbox, free aliases** — no new paid mailboxes. `orders@aevia.at` and
  `hello@aevia.at` will alias onto `xenia@aevia.at` (M365 supports ~300-400 free
  aliases per mailbox). Aliases are reassignable later at no cost if the owner gets
  his own mailbox — not a one-way door.
- **Do NOT touch the existing SPF record.** Verified via Brevo's own docs: Brevo
  authenticates via DKIM alignment alone, not SPF — adding an `include:` for Brevo
  would not actually help (their envelope sender doesn't align with `aevia.at`
  anyway), and the current SPF has a hard fail (`-all`) — editing it would be pure
  risk for zero deliverability gain. **Left untouched, confirmed correct.**
- **Artist-enquiry emails default to `hello@aevia.at`** (was previously hardcoded to
  `xenia@aevia.at` directly) — this is a default pick, not owner-confirmed; flagged
  as an open question in the brief.
- **Added the missing post-payment customer email** opportunistically in the same
  pass as the migration, since it's the identical code path (TO-DO #56 closed).
