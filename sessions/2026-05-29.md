### Staff + customer engine integration fixes

**Context:** Live testing revealed customer preview loaded template but not photos, and the two engines didn't match.

### Customer preview photos not loading
**Root cause:** `loadPhotos()` did `Object.entries(signedUrls)` which gave top-level keys (`cover`, `special`, `pool`) as "filenames" — fetching null/objects instead of URLs. Also `bookSequence` never returned by `getOrder`; fallback ignored `pageCount` + `fpSelections`. Also `bookAssignments` never populated (no `assignPhotosToSpreads`).
**Done:** Rewrote `loadPhotos()` to handle nested structure. Added `buildBookSequence()` (copy from staff engine). Added `assignPhotosToSpreads()` (adapted from staff engine). Fixed 3x broken sequence references.

### Save book state
**Decided:** Option A — explicit "Save book state" button in staff engine order info panel. Simple, clear, staff-controlled. Chosen over auto-save (too complex for MVP volume) and on-navigate save (silent/stale risk).
**Done:** New `saveStaffState` Cloud Function (staff key auth, writes `staffBookAssignments` + `staffBookCaptions`). "Save book state" button in order info panel. `getOrder` returns these fields. Customer preview uses `staffBookAssignments` if present, falls back to auto-assign.
**Firebase Functions deployed.**

### Customer preview photo structure fix (systematic debugging)
**Root cause (RC1):** `loadPhotos()` put cover + special + pool all in `window.photoPool`. Staff `bookAssignments` indices address a pool-only array. Every index was wrong — cover photo landing in first pool slot, FP photos in pool slots 1/2.
**Root cause (RC2):** Customer `renderSpread()` had no code for `slotDef.pool === 'special'`/'artwork'. FP special photo slots rendered empty.
**Root cause (RC3):** `window.specialPhotos` never initialised in customer preview.
**Done:** `loadPhotos()` now splits: cover → `specialPhotos.cover`, FP photos → `specialPhotos[FPX]`, pool → `photoPool` only. `renderSpread()` now handles special/artwork slots via `specialPhotos[spreadId]`. Dominant orientation detection mirrors staff engine (allArtwork path for FP5, special-slot fallback for FP3/FP4).
**Watch out for:** Customer preview still has no dedicated cover canvas (staff engine has a separate front/spine/back panel). SP0 renders correctly as first inside spread. Cover panel is a separate decision — open question in STATUS.md.
**Still untested** — user will verify next session.
