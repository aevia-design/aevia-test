## Session 8 (2026-05-29) — customer engine parity + UX

### Meta-task (user, explicit)
Customer-rendered book must look EXACTLY like staff (fonts, styling, captions, photo positions, spreads, cover) across the WHOLE book. Customer can change photo sequence AND captions, but always using our styling/fonts/layout. This is the bar for "done" on the customer engine.

### Root-cause pattern for all divergence
Customer preview was built as **partial, drifted reimplementations** of the staff engine's functions (renderSpread, renderCover, textPanel, captions). Every divergence traced to: (a) staff not SAVING some state, or (b) customer recomputing it differently. The robust fix is always: staff saves the fully-resolved value; customer replays it verbatim. See [[feedback-engine-parity]].

### Order confirmation wording
**Done:** Rewrote 3 steps on `pages/order.html` success screen (Design/Approval/Print). Removed "print in Vienna"; "PDF preview" → "preview link".

### Replay staff-saved book (sequence + cover)
**Decided:** Save the resolved book sequence (`staffBookSequence`) on "Save book state"; customer uses it instead of recomputing `buildBookSequence`.
**Why:** Staff can manually reorder/add/remove spreads; only assignments were saved, so customer rebuilt the default sequence and every index landed on the wrong spread → spreads out of order / "missing".
**Done:** `saveStaffState` + `getOrder` carry `staffBookSequence`. Customer renders cover first (ported read-only `renderCover`) and added the `heartClip`/`fullBleed` slot branch (birthday heart).
**Watch out for:** `staffBookSequence` only exists on orders saved AFTER this deploy. Older orders fall back to recompute.

### Caption styles never persisted
**Root cause:** "Save book state" sent only assignments + captions + sequence — NOT `coverCaptionStyles` or `spreadCaptionStyles`. Customer fell back to CSV defaults → wrong font/weight/size everywhere.
**Done:** Both style maps now saved (`staffCoverCaptionStyles`, `staffSpreadCaptionStyles`) and replayed. Customer slot captions now mirror staff `valign` (bottom/center) positioning. Cover caption text saved/rendered as innerHTML (multi-line preserved — was textContent, single-line).

### FP text-panel parity (birthday / funny words)
**Root cause:** Customer textPanel was a stripped copy missing the `funnyWords` branch, `valign` anchoring, and the pt-vs-px font sizing.
**Done:** Ported staff textPanel faithfully — funnyWords uses `sizePt*SCALE px` + formatFunnyWords (max 10 words, one per line); regular panels use `sizePt + 'pt'`; added `applyTypographicRules` (NBSP after preps + widow prevention).
**Watch out for:** regular text panels use raw `pt` units (96dpi), funnyWords uses `*SCALE px` — this asymmetry is intentional and matches staff. Do not "normalise" it.
