### The shape of the work

The owner asked whether a separate markdown file should track the translations, so the German
could be checked against the proven English. **Decided: no separate file — the string table is
the tracking artefact.** Each key is `{ en, de }` on one line, so the pair sits in front of the
reviewer, and because the page now reads its *English* from the table too there is only one copy
of each string. A markdown master would have given the same review view and then drifted, which
is the failure the owner was actually worried about.

Delegation was raised and declined by the owner: **delegate only very straightforward tasks.**
Even the short placeholders carry brand voice, so all of it was done inline.

### 2026-08-14 — Stage 4 is two layers, and the brief only described one

**Found before writing anything:** the form renders `cap.label` and `cap.placeholder` straight
from the template data files into the customer's screen (`order.html:946`). So Stage 4 is
**(a)** the form's own chrome and **(b)** ~386 per-template string fields across 11 data files
(~245 unique once the four identical Heirloom colourways are discounted). The brief's one-line
description covers only (a).

Layer (b) is the `svgDe` pattern again: `labelDe` / `placeholderDe` / `hintDe` beside the
English, resolved by a new `tdText()` helper with the same fallback — no German means English,
never blank.

### 2026-08-14 — Stage 4a: the chrome, and two things only German exposed

**Done:** `5eec41b`. `assets/js/order-strings.js`, `t(key, vars)` for JS-built markup,
`data-i18n` / `-ph` attributes plus one `applyStrings()` pass for static markup.

Two bugs surfaced that English never would have:
- **The nav CTA collided with the nav links at 1440px** — "Unsere Kollektionen" is wider than
  "Our Collections". Fixed with a gap on `.nav` and a non-shrinking CTA.
- **German adjective endings agree with the noun's gender**, so the Newborn birth-story closing
  line cannot be built by lowercasing the customer's word the way English does. The whole phrase
  is one key per gender; the gender field is free text, so the match accepts both languages.

**Watch out for:** `git commit` rewrites line endings, so a `git diff --stat` on this file
overstates the change. Judge by the tests, not the diff size.
