### — Cover caption colour wired end-to-end from CSV
**Done:** Added `Captions_1_fontColor` / `Captions_2_fontColor` columns to `Scribble_Template_Sizing_Cover.csv`. `parseCoverCsv` reads them; `serializeCover` emits `color: '#...'` on each cover caption. `drawCoverCaptions` now resolves and applies the colour via a local `resolveCapColor()` (hex only — cover doesn't use named colours).
**Watch out for:** Front captions previously rendered as black because `pg.drawText` was called without a `color` param. Now both rotated (spine) and non-rotated (front) captions get the colour. If a hex isn't 6 chars or is missing, falls back to near-black `CAPTION_COLOR`.

### — Spine caption rotation direction and positioning fixed
**Done:** Two bugs: (1) `angle: capDef.rotate || 270` produced 270° CCW in pdf-lib = text reading DOWNWARD. CSS `rotate(270deg)` CW equals 90° CCW in pdf-lib. Fix: hard-code `angle: 90`. (2) Positioning math had x/y roles swapped — `xMm` (horizontal spine center) was used as the y-axis target and vice versa. After 90° CCW rotation, the drawText `x` parameter controls horizontal position on spine; `y` controls vertical position along spine length. Rewrote spine branch with correct math.
**Watch out for:** pdf-lib uses standard math convention (CCW = positive); CSS uses CW = positive. Any future rotation work must convert: `pdf_angle = 360 - css_angle`. After 90° CCW rotation, character body extends LEFTWARD from drawing baseline (x) by approximately cap height, and UPWARD from drawing baseline (y) by text width.

### — Spine horizontal centering refined with font ascender height
**Done:** First fix used `sizePt / 2` as the rotation centering offset — but cap height of typical fonts is only ~70% of `sizePt`, so visual centre ended up biased to one side. Switched to `font.heightAtSize(sizePt, { descender: false }) / 2` (ascender height) for accurate centering on uppercase spine text.
**Watch out for:** This assumes uppercase-heavy spine text (ANN, 2026). For mixed case with descenders the offset is still slightly biased; not worth solving now.

### — Engine caption font size was 26% too big (CSS pt at 96dpi)
**Done:** Root cause: `captionEl.style.fontSize = sizePt + 'pt'` — browsers resolve CSS `pt` at 96dpi (1pt = 1.333px), but the engine canvas is ~76dpi (SCALE=3 px/mm). Result: a "14pt" caption rendered as 18.67px on screen instead of the correct 14.82px for print-equivalent. Captions appeared larger than the PDF and wrapped differently. Fix: convert pt → canvas px explicitly using `sizePt * SCALE * 25.4 / 72`. Applied in both `renderSpread` (line ~2033) and `applyStyleToSpreadCapEl` (line ~1623, the toolbar live-update path).
**Watch out for:** Do NOT use CSS `pt` units anywhere that needs to match print scale. The FunnyWords panel already uses `sizePt * SCALE` (px) by deliberate convention — leave that path alone. If a future template uses a different SCALE, the formula auto-adjusts.

### — Medium style (weight 500) was never reaching the PDF
**Done:** `drawCoverCaptions` and `drawCaptions` both resolved style as `>=700 → bold`, `>=600 → semibold`, then dropped straight to `italic/regular`. Weight 500 (Medium pill in engine) fell through to 'regular'. `NT Somic_medium` was in FONT_FILE_MAP but never reached. Added the `>=500 → 'medium'` branch in both functions.
**Watch out for:** EB Garamond has no `_medium` variant — it's a variable font and would fall back to `_regular` via `lookupFont`'s fallback. Acceptable for now.

### — `upper-right`/`lower-right` captions were overflowing the page; `above`/`below` got `wrapText` too
**Done:** Root cause: pdf-lib does NOT auto-wrap. Right-margin captions had no width constraint — they drew the full text string and bled off the page edge. Added `wrapText(font, text, sizePt, maxWidthPt, charSpacing)` helper that word-wraps to fit, with character-level fallback for words wider than the line. Applied to all three branches. The width formula matches the engine's: gap from photo = `capDef.offset` (mm, NOT a hardcoded 2mm), right padding = 2mm to mirror the engine's 6px gutter.
**Watch out for:** Initial fix used a fixed 2mm gap which gave the PDF more room than the engine and made wrap points differ (PDF fit one extra word per line on FP3 left V upper-right). Use `capDef.offset` for the gap so engine and PDF produce identical line breaks.
