### — PDF photo placement root causes found + fixed

**Done:** Systematic debug of why photos were "placed randomly." Two root causes found and fixed.
**Root cause 1:** book-state.json exported before orientation tracking was added → all assignments were plain strings → `pickVariant()` always returned 'H' → spreads that should be V used H slots (completely different coordinates). Fix: user must re-export book-state.json with current template engine (code already correct, just stale file).
**Root cause 2:** SVG overlay resized to `FULL_PX × FULL_PX` (206mm bleed canvas) instead of `CONTENT_PX × CONTENT_PX` (200mm content area) and placed at (0,0) instead of (BLEED_PX, BLEED_PX). SVG content was designed for 200mm — stretching to 206mm caused ~3% misalignment of the frame relative to photo slots. Fixed.
**Watch out for:** Photo coordinate math (`slotLeft = (x - w/2) * MM_TO_PX + BLEED_PX`) was already correct — verified proportionally against browser tool. Do not change it.

### — FP1 heart clip implemented in PDF

**Done:** FP1 birthday right page — photo was rendering as a rectangle behind the SVG overlay. Fixed by detecting `slot.heartClip === true`, creating an in-memory SVG mask from the same heart path used by the browser CSS clip-path (scaled from 600px canvas space to CONTENT_PX = 2362px), applying it via Sharp `blend: 'dest-in'`, and placing the masked photo at (BLEED_PX, BLEED_PX) covering the full content area.
**Why:** The browser uses CSS `clip-path: path(...)` on the slot div; Sharp has no CSS equivalent, so we rasterize an SVG mask. The heart path coordinates are in 600px canvas space (not slot-local space) — scale by `CONTENT_PX / 600`.
**Watch out for:** The heart slot in template-data.js covers the full page (slot.w/h ignored for placement) — photo is resized to CONTENT_PX × CONTENT_PX, not to slot dimensions. This differs from all other slots.

### — Caption rendering implemented (Plan 11-03)

**Done:** Added `drawCaptions()` to export-pdf.js. Uses pdf-lib text drawing with `@pdf-lib/fontkit` for custom font embedding. All 6 fonts (NT Somic Regular/Medium, EB Garamond Regular/Italic/SemiBold, FirstTimeWriting) embedded with `{ subset: false }` to avoid woff2 glyph extraction errors. Captions drawn as vector text on top of the rasterised page PNG. Handles slot captions (below-slot positioning) and textPanel captions (FP spreads, centered at 100mm).
**Watch out for:** `{ subset: false }` is required for woff2 fonts with pdf-lib/fontkit — without it, all characters render as dots ("can't extract NT Somic Regular-2525" warning). This increases PDF file size slightly but is correct. Caption vertical position uses `sizePt * 0.75` as baseline offset — may need visual tuning per font.
**Decided:** Captions are vector PDF text (not baked into the rasterised PNG). This is the right approach for print quality — text stays sharp at any zoom.

### — woff2 → TTF font migration + unified COVER_FONTS

**Done:** Replaced all woff2 font references with TTF files in template-engine.html @font-face and export-pdf.js FONT_FILE_MAP. Added NT Somic Bold. EB Garamond now uses variable font TTFs.
**Decided:** `{ subset: false }` not enough — woff2 is a compressed container fontkit cannot parse at all regardless of options. TTF/OTF required.
**Watch out for:** EB Garamond SemiBold has no static TTF — the variable font maps to it but PDF viewers don't honour weight axes, so semibold captions render at ~400 Regular in PDF. Known and accepted.

### — Art gallery inline bold/italic on selected text

**Done:** Added B and I buttons to caption toolbar (spread mode only, hidden for cover). Uses `document.execCommand('bold'/'italic')` on the text selection — inserts `<b>`/`<i>` tags. Slot captions now save/restore `innerHTML` instead of `innerText` so markup persists. export-pdf.js strips HTML tags via `stripHtml()` before drawing text (inline styles are browser-only for now).
