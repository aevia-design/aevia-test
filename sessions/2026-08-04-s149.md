## How the session started

Owner asked for advice on a third-party GitHub plugin (`wan-huiyan/agent-review-panel`) —
a multi-agent "expert panel" that reviews content from 4–6 perspectives, debates, then a
judge arbitrates. His goal: a 360° reliability/security/PRD-alignment view across engines,
website and dashboard.

**Recommendation: don't.** Two reasons, and the second turned out to be the important one.

1. Installing an unvetted plugin gives a stranger's instructions filesystem access in a repo
   that sits next to `functions/serviceAccountKey.json`, `functions/.env` and
   `motif-engine/.env`. Wrong risk to take while trying to *reduce* risk.
2. **It is a diff-shaped tool and the question is not diff-shaped.** The panel — like
   `/code-review`, like `/code-review ultra` — reviews an artefact you hand it. The owner's
   question is about the system already built across 148 sessions. Running `/code-review`
   proved the point: it returned "(none)" because the only pending change was a Markdown
   brief. `ultra` would have returned the same nothing and billed for it.

Also clarified (owner asked): `/code-review` local is normal session usage; `/code-review
ultra` is a cloud multi-agent review billed to **usage credits**, separate from plan usage,
and Claude Code stops for confirmation before charging. Docs: `code.claude.com/docs/en/code-review`
and `/docs/en/ultrareview`.

## Built (all unrun)

### `qa/p2-upload-probe.mjs` — new, TO-DOS #88

Automated half of the upload-stall investigation. Defaults to **WebKit**. Keeps a ledger of
every GCS PUT — status, duration, outcome — so a stall registers as **never-resolved**
rather than a hung script with nothing to show. Prints a **slot → file map**, the one
observation the brief calls decisive.

- `--reuse` (default) pins ONE photo into cover + every special zone + the whole pool,
  the strongest form of H1 (duplicate source photo). `--distinct` is the control.
- `--throttle[=slow3g|fast3g]` for H2 (the retry is 3 × 100/200 ms, so ~50 benign
  `ERR_ABORTED`s on a fast link may exhaust it on a slow one). Real CDP conditions on
  Chromium; on WebKit an approximate per-request delay — **indicative only**.
- `--device`, `--dry-run`, `--headed`, `--browser`.
- Behaves like every other minting script: real order, normal emails.

### `qa/p0-1-template.mjs` — extended, all flags default-off

Existing runs and the P0 baseline are unchanged.

- `--device="iPhone 13"` — real phone profile. **Every screenshot doubles as a
  horizontal-overflow check**, raising an S2 per step that side-scrolls. Covers the wizard
  steps `mobile-audit.mjs` never reaches.
- `--browser=webkit` — Safari engine. With `--device` this is the closest available to a
  real customer.
- `--heic=N` — swaps the **tail** of the main set for real `.heic` files from
  `assets/test photos/` (IMG_5249/5256/5260). Replaces rather than appends because the photo
  count must match the target exactly (S124 gotcha). "No preview" tiles are expected and not
  flagged; an S1 fires only if the grid ends up short.
- Run artefacts go to a **suffixed** directory so a phone run can't overwrite the desktop
  baseline.

Both scripts pass `node --check`. Neither has been executed.

## Watch-outs for the next session

- 🔴 **Do not run QA until Xenia confirms her email rules are settled.** Any order-minting
  script emails staff on creation (`createUploadSession`, failure mode D2) — unavoidable.
- 🔴 **Playwright's WebKit is not Safari** — same rendering/JS engine, different networking
  stack, no ITP. The suspected fault is *in* the transport layer, exactly where they
  diverge. A reproduction is gold; **a clean pass proves nothing.** The authoritative test
  stays a real Safari order on Xenia's Mac.
- ⚠ **The new scripts have never run.** `qa/test-photos/` is gitignored and local-only, so
  they could not be smoke-tested here. Expect the phone runs to need selector fixes — these
  screens have never been driven at 390px. If a phone run passes first time, be suspicious.
- **Prerequisite:** `npx playwright install webkit` — a Chromium-only install won't have it.
- **Keep `--heic` small** — each HEIC is one `convertHeic` Cloud Function invocation.
