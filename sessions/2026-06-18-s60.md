### ~17:00 — Fetch concurrency throttle (MAX 6→3)
**Decided:** Lowered the in-page `window.fetch` throttle from 6 to 3 concurrent.
**Why:** S59 believed throttling was "what actually fixes it." It is not.
**Result:** Still ~2 fail (photo_015, photo_030). Concurrency ruled out.

### ~19:10 — deviceScaleFactor 3→2 (memory hypothesis)
**Decided:** Tested whether renderer image-decode memory was the cause. Wander loads huge
embedded-raster SVG overlays (SP04 ~18 MB, SP10 ~12 MB, SP03 ~6.5 MB, cover ~4.2 MB) that
Newborn doesn't — decode memory scales with rendered px = layout × scale².
**Why:** Explained "only Wander fails" + "fine in real browser." Looked very promising.
**Result:** RULED OUT. Halving decode memory (3→2, ~2.25× less) left the failure count
**unchanged** at exactly ~2 (photo_045, photo_030). If memory were binding, the tipping
point would shift. It didn't. Restored scale to 3 (pure quality knob, memory irrelevant).

### ~19:20 — Force HTTP/1.1 (--disable-http2 --disable-quic, transport hypothesis)
**Decided:** Headless multiplexes all parallel GCS fetches over one HTTP/2/QUIC session;
hypothesised it resets ~2 streams under load and retry reuses the degraded session.
**Why:** Fit retry-proof + random + headless-only.
**Result:** RULED OUT. Still ~2 fail (photo_046, photo_052). Reverted the flags.

### ~19:30 — page.route → refetch via Node (architectural fix attempt)

## Other findings
- **The in-page retry was barely working.** Each failing photo logs `requestfailed` exactly
  ONCE, not 5×. If the 5× retry override were re-attempting them, a permanently-failing photo
  would log ~5 events. So S59's "retry covers transient drops" was largely inert — likely why
  retry never helped.
- **Why Newborn (AEV-039) sailed and Wander (AEV-040) struggles = photo COUNT, not size.**
  Wander order is 50+ pool photos; the "~2 drop under concurrent burst" is roughly fixed, so
  small orders stay under it (0 drop) and big ones clip ~2. Not a Wander-specific corruption.
- **Cover-wrap naming already works for Wander** — `compose-all.mjs` reads the order-stamped
  `cover-wrap-AEV-040.png` (stable `cover-wrap-newborn.png` is just a fallback alias). No fix
  needed there. The ONLY blocker is the photo-fetch load failure.
