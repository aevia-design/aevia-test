## 4 — Pass C (`9ea3cf5`) — items 7 + 8
Both bugs are the same shape: **`order.html` is the third surface of the template seam and kept
Wander-era hardcodes the engines had already outgrown.** Instrumented both before touching either;
used Wander as a **control template**, which is what made each root cause obvious in one run.

- **[7] Map preview rendered no images.** `renderRegionMap`'s `ASSET_BASE` was hardcoded
  `'../assets/Template_Wander/'`. Joyride's assets sit under an `SVG/` subfolder **and** use different
  map filenames → every request 404'd. Measured: all 4 canvas images + right-page SVG at
  `naturalWidth 0` for Joyride vs `200`/4056×4056 for Wander. **Fix:** `TEMPLATE_REGISTRY` now carries
  `svgBase` per template, mirroring the engine + customer-preview registries (same relative depth as
  customer-preview — both in `pages/`). Closes the seam gap instead of special-casing Joyride.
  **Bonus found while instrumenting:** itinerary font hardcoded to Cormorant Garamond (Wander's face)
  → now read from the textPanel caption's own `font`; **Mulish registered on `order.html`** alongside
  Cormorant (every map template's face must be registered there).
- **[8] Photo count.** `calcPhotoTarget` hardcoded `stdIds` to SP1–SP6 → Joyride's **SP7/SP8/SP9 never
  entered the sequence**. Engine + customer-preview were de-hardcoded at S129; the order form was
  **missed**. Now derives from the template's own spread keys.
  ⚠ **The reported "43 vs 46" was two different configurations** — 43 = map only, 46 = Intro+Map. The
  real defect was a consistent **4-photo undercount in every Joyride config**. Live order form now
  returns **49** (no FPs) / **46** (Intro+Map) — exactly the engine's numbers.
- **New `tests/photo-count-sequence.test.js`** (15 tests): pins the engine's counts, asserts **every
  template's standard spreads are reachable** (the invariant the hardcode broke — catches this for any
  future template), pins the other five templates' unchanged counts, and **tripwires** the derivation
  in `order.html`. Confirmed **red** against the old hardcode before trusting it.
- **Why nothing caught this:** both engines were correct so `engine-parity` stayed green; the order
  form's count had no test (`photo-count-guard` only checks the *message*); and the other five
  templates only have SP1–SP6, so the hardcode was **coincidentally correct** until Joyride.
