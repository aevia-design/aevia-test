**Watch out for:** the order is **push → wait for deploy → capture**. Verify the deploy by

not proof of a missing file** — three of nine mockups 404'd while the rest served, and the
same URLs returned 200 a minute later. The edge rollout is not atomic.

`web-mockups.mjs` had **no Laguna entry at all** — it feeds the collections card's

**Watch out for:** the first run baked every spread on a **near-white** backdrop. The warm
grey is **opt-in** — `BG_R=216 BG_G=212 BG_B=207` — and the default (240) was set that way
in S98 so regenerating one template could not disturb the four then-live. The output is
*plausible*, so it only reads as wrong beside another product page. Verified the fix by
sampling corner pixels: **226,222,218** for spreads, **219,215,211** for flats, identical
to Scribble and Wander. `compose-closed.mjs` ignores the env and stays at 240 — matching
the other templates, so the collections card was never affected.

**Also:** `smoke-laguna-product.mjs` asserted the **opposite** of what it should once the
images landed — it checked that missing mockups degrade to a grey "Preview soon" box. It
briefly read 40/42 for the best possible reason. Now asserts every gallery image **loads**
via `naturalWidth`, not DOM presence. 44/44.

**Curiosity explained:** every cover-wrap capture writes **two** files — the order-stamped
one plus `cover-wrap-newborn.png`, a fixed-name alias the three compositors fall back to.
Nothing to do with the Newborn template; a fossil from the first template ever captured.
`compose-all` prefers the order-stamped file. Confusing name, no function. Worth renaming.
