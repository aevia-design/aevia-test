### 13:00 — #9 PDF cover + SVGs were NaN (root cause)
**Done:** Moved `SPREAD_SVG_BLEED_UNITS`, `BLEED_PT`, `COVER_FULL_W_PX/H_PX/BLEED_PX` into `initializePrintConstants()` in `scripts/export-pdf.js`.
**Why:** chunk-007 made `MM_TO_PX`/`BLEED_MM` lazy (loaded async in `--order` mode), but these five constants were still computed at module-load time → `undefined` → `NaN`, which corrupted every SVG viewBox ("bad dimensions") and the cover canvas create.
**Watch out for:** Any new constant derived from `MM_TO_PX`/`BLEED_MM`/`MM_TO_PT` must be assigned inside `initializePrintConstants()`, not at module top. `COVER_SVG_BLEED_UNITS` is fine at load (uses literal `COVER_BLEED_MM`).

### 13:00 — #4 scroll stall: downscaled thumbnails (root cause)
**Done:** Order form now generates a ~240px display thumbnail per photo (`makeThumbUrl` via createImageBitmap → canvas → JPEG blob) and uses it for the grid tile. Restored `content-visibility:auto`.
**Decided:** Downscale on the client, display-only. Rejected: removing `content-visibility` alone (made it WORSE — Chrome held all 49 full-res decodes ~2.5GB and evicted them → grey squares).
**Why:** Grid `<img>` pointed at full-res originals (~14MB, ~50MB decoded each). 49 of them thrashed Chrome's decode cache.
**Watch out for:** The thumbnail is browser-only — never uploaded, never reaches GCS or the PDF. Full-res `_objUrl` is preserved for the lightbox + the GCS upload (`fileObjects`). Lightbox click must stay on `_objUrl`. `removeMainFile` revokes both `_objUrl` and `_thumbUrl`.

### 13:00 — #6 birthday text box: engine vs PDF mismatch
**Done:** Replaced the fixed `paddingTop` hack with flexbox vertical centering (`display:flex;flex-direction:column;justify-content:center`) in both engines for `valign:'center'` textPanels.
**Why:** The PDF already centered via `(boxHeight − textHeight) / 2`; the engine pinned text ~35% down with dead top space. They never matched. User chose "just fix centering" over adding Top/Mid/Bottom toolbar buttons (PDF already supports valign top/center/bottom from CSV, but reads `capDef.valign`, not an override — so a future toolbar valign control would also need the PDF to read `ov.valign`).
