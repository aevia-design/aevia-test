## What shipped (3 commits on `main`)

### 1. Block inline rich-text formatting in caption editors (`027931d`)
**Problem:** caption boxes are `contentEditable='true'`, so Ctrl+B/I bolded text on screen
but the PDF's `stripHtml()` dropped it — screen promised formatting print couldn't keep.
The toolbar is already whole-caption-only (font/weight/italic/size/spacing/align), which
both engine and PDF honor; only the browser shortcuts + paste diverged. (The Intro/text
panels already round-tripped through plain text, so they were unaffected — that was the clue.)
**Fix:** one document-level `beforeinput` guard on BOTH surfaces (engine + customer-preview)
that `preventDefault()`s any `inputType` starting with `format`. Blocks Ctrl+B/I/U etc.;
leaves `insertText`/`insertLineBreak`/paste untouched. Also fixed the stale comment at
`rebuildStylePills` claiming B/I buttons exist (they don't).
**Verified:** 102/102 tests; new `qa/verify-format-block.mjs` drives REAL Ctrl+B/I keystrokes
against both live pages → text stays plain. (Note: `execCommand('bold')` does NOT fire
`beforeinput` in Chromium — must test with real `page.keyboard.press`, not execCommand.)

### 2. Slim customer-preview footer (`09ffec8`)
The full marketing footer (Products/Company/Support storefront nav) leaked into the
customer review/approve page, its links pulling customers away mid-conversion. Replaced
with one quiet centered line: `© 2026 Aevia · Questions about your preview? Get in touch`
(→ `help.html#contact`). Dropped the dead "Terms of service" span (no terms page existed).
Trimmed now-dead column CSS + reduced footer padding (64px→28px). Screenshot-verified.

### 3. Always restore saved book state on order load (`ca44ab2`)
**Footgun:** loading an order with a saved book state popped a native `confirm()` where
**Cancel/Esc = discard the saved layout** and auto-arrange fresh. The saved state holds the
customer's APPROVED layout (`approveOrder` merges customer* → staff* at approval), so an
accidental Cancel → Save would silently overwrite the customer's work, no undo. Cancel itself
only mutated the in-memory order (no backend write), so it was reversible until a Save — but
the convention-breaking dialog (destructive on the Esc path) was the risk.
**Decision:** no real use case for deliberately discarding an approved book (YAGNI — add a
guarded explicit button later if one ever emerges). Removed the prompt; always restore when a
saved state is present. The existing `restoring` logic (line ~4205) already handled the load.
**Verified:** 102/102 tests (pure branch removal). NOT browser-confirmed — needs staff login +
a real saved order; logic is a straight deletion.
