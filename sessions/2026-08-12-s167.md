### 09:26 — The push was blocked by the environment, not the code

`git push` failed on the pre-push hook: `❌ could not start http-server on :8080`. The order
harness spawns `npx http-server` and gives it 15 seconds (30 × 500ms) to bind. npx's cold
start beat that timeout. Nothing was wrong with the order flow.

**The harness reuses an already-running server** (`serverUp()` is checked before spawning), so
starting one by hand and re-pushing was the whole fix. 12/12 green on the retry, including
S166's new Ch6 assertion that the low-res badge names the cause and the fix.

Worth carrying: **a blocked push here is more likely to be the server start than the order
form.** Read which line failed before assuming a regression.

### 09:40 — Joyride was missing from BOTH compositor tables

The owner had already captured AEV-069 (cover-wrap + 20 spreads + manifest) and asked for the
second half of the pipeline. It could not have run:

- **`scripts/compose-all.mjs`** — `Unknown template 'joyride'`. Its `TEMPLATES` map names each
  template's data file and the global it assigns to, and Joyride was absent. The data it needs
  (`cover.mockupEdges: front #efe7d3, spine/back #f2c7de`) was already in `joyride-data.js`.
- **`scripts/exp2-images.mjs`** — no entry, and it exits rather than half-working.

Both fixed, so a re-capture from a different order is now a one-liner. The crop step's
`resolveSpread()` accepts bare book-sequence ids (`sp1`) as well as literal composite names
(`open-01-sp1`), so the entry does not have to encode where in the book each spread landed —
**and that index shifts with photo count, so bare ids are the right choice for new templates.**

Manifest read before composing: `FPintro` at index 00, `FP1` (travel map) at 11. AEV-069 is a
40pp book whose spreads repeat (SP1–SP9, then SP1–SP9 again), so `sp1` resolves to the first
occurrence, `open-01-sp1`.
