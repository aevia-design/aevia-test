### De-hardcoding considered and dropped (YAGNI)
- Evgeny floated lifting the engine's hardcoded constants (`pageSize 200`, `bleed 3`,
  `canvasPx 600`, `scale 3`, 3-panel cover) into the data file, by Excel-model analogy
  (never hardcode; cross-link to assumptions).
- **Killed by its own logic:** you cross-link *assumptions* (vary per scenario), not
  *constants* (π). For launch every book is 200mm square, same bleed/canvas, same
  3-panel cover — only colours/elements vary, and those are already data. So the
  hardcoded values are constants; moving them changes nothing anyone sees.
- Memory `project_dehardcoding_dropped.md` records this. Re-raise only when a template
  with genuinely different geometry is designed (prime suspect: cover construction).

### Wander order flow (commit 9182309)
- **`order.html` template-aware.** Was hardwired to `SCRIBBLE_DATA`. Now loads
  `wander-data.js` too and resolves the active template via a `TEMPLATE_REGISTRY` /

  Cover-photo requirement + file push are now conditional on `coverHasPhoto()`.

  "Optional add-ons" (Route map / Caption overlays — fake, unwired, wrong param format)
  with a real "Optional spreads — all free" → Travel-map FP1 (`data-fp/data-photos`),
  a photo counter, and `goToOrder` now sends the correct `addons`/`addon_inputs`/
  `addon_slugs` contract (was `addonName`, which order.html ignored).
- **FP1 country-select UI** (new control type). Region-grouped `<select>` built from
  `mapCoordinates`, removable country tags, `sameRegionOnly` enforcement (cross-region
