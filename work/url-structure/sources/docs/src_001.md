# URL Structure Best Practices for Google Search

Source: https://developers.google.com/search/docs/crawling-indexing/url-structure
Publisher: Google Search Central (Google for Developers)
Last updated (per page): 10 December 2025
Retrieved: 2026-09-23 via WebFetch (summarized extract)

## Core Guidance

Google emphasizes creating crawlable, intelligible URL structures. Poor URL design can severely impact crawlability, causing "extremely high crawl rates, or not at all."

## Key Requirements

URLs must comply with IETF STD 66 standards and avoid fragments for content changes. Google recommends standard parameter encoding: equal sign (`=`) to separate key-value pairs and ampersand (`&`) to add additional parameters.

## Best Practices Summary

- **Simplicity & Readability**: Use descriptive words rather than ID numbers. Example: `example.com/wiki/Aviation` (good) vs. `example.com/index.php?topic=42&area=3a5ebc944f730f1` (poor).
- **Language & Encoding**: Use the audience's language; percent-encode non-ASCII characters.
- **Word Separation**: "We recommend using hyphens (-) instead of underscores (_) to separate words in your URLs" — hyphens clarify concepts better for users and search engines.
- **Parameter Minimization**: Remove unnecessary parameters that don't alter content.
- **Case Sensitivity**: Standardize capitalization — Google treats `/APPLE` and `/apple` as distinct URLs.

## Common Issues to Avoid

Additive filtering, irrelevant parameters (referral IDs, session IDs), calendar pagination, and broken relative links create problematic URL proliferation that wastes crawler bandwidth.
