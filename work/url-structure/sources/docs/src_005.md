## Basic Syntax

The `_redirects` file uses line-based declarations: `[source] [destination] [code?]`. Source and destination are required; HTTP status code defaults to 302 if omitted. Lines starting with `#` are comments.

## Splats and Placeholders

Splats (`*`) perform greedy matching of all characters, referenced in destinations via `:splat`. Placeholders like `:placeholder_name` match characters excluding delimiters (periods in hostnames, slashes in paths).

## Proxying with 200 Status

A 200 status code enables proxying — content is served from the destination path while the original URL is retained in the browser ("only the first redirect in your file will apply" in this mode). Cloudflare's docs warn: "proxying pages can have an adverse effect on search engine optimization" due to duplicate content concerns.

## Limits and Precedence

Combined maximum of 2,100 redirects (2,000 static, 100 dynamic). Each declaration ≤1,000 characters. "The order of your redirects matter" — the topmost matching rule applies; static redirects should precede dynamic ones.

## Key Constraint

Redirects do not apply to Pages Functions routes; behaviour for those must move to function code or be excluded via `_routes.json`.
