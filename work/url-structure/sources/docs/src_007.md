# Localized Versions of Your Pages (hreflang)

Source: https://developers.google.com/search/docs/specialty/international/localized-versions
Publisher: Google Search Central (Google for Developers)
Retrieved: 2026-09-23 via WebFetch (summarized extract)

## Purpose

hreflang helps Google identify localized page versions across languages/regions so users get the most appropriate content variant.

## Required Tags

Three equivalent implementation methods:
- HTML tags: `<link rel="alternate" hreflang="[lang_code]" href="url" />` in page header
- HTTP headers: `Link:` response headers for non-HTML files (e.g. PDFs)
- Sitemaps: `<xhtml:link>` elements within XML sitemap entries

## Self-Reference Rule

"Each language version must list itself as well as all other language versions." If page X references page Y, Y must reciprocally reference X, or annotations may be ignored entirely.

## x-default

Reserved value as fallback for unmatched user languages, typically on a language-selector page: `<link rel="alternate" href="https://example.com/" hreflang="x-default" />`.

## URL Structure Requirements

Alternate URLs must be fully-qualified (with protocol). URLs need not share a domain, though bidirectional linking matters for maintenance.

## Common Errors

- Missing reciprocal links between pages
- Invalid language codes outside ISO 639-1
- Region codes alone without language codes (e.g. `be` instead of `de-BE`)
- Unsupported region codes like "EU" or "UK"
