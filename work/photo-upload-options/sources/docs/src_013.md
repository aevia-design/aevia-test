# Dropbox API Documentation - Chooser (pre-built component)

Source: https://www.dropbox.com/developers/chooser (redirects to https://docs.dropboxapi.com/dropbox-api/docs/pre-built-components/chooser)
Accessed: 2026-09-24 (WebFetch extract, official Dropbox documentation)

## Extracted content
The Chooser is a small JavaScript component that lets a web app get files from a user's Dropbox without implementing a file browser, OAuth flow, or storage/token management. Users authenticate through Dropbox's own popup using their existing Dropbox web session - the integrating app never needs an access token or OAuth for this component.

Technical facts:
- Integration = one script tag (with an app key) + a JS call to open the chooser.
- `sizeLimit` option can cap the size of each selected file, in bytes (no universal platform-wide max stated in this doc).
- Browser support must be checked via `Dropbox.isBrowserSupported()`; unsupported browsers show a greyed-out button with a warning.
- No production/app-review approval is required before going live - "you can publish your integration to your users as soon as you're ready."
- Setup requires creating a Dropbox app in the developer console and registering the app's domain(s).

## Notes
Directly answers research question 3's Dropbox technical facts: Chooser is markedly lower-effort than an OAuth-based integration (no server-side token handling, no app review), which is a meaningful asymmetry versus Google Photos Picker API or Drive Picker (both of which sit behind Google's OAuth consent/verification process). This favours Dropbox as the technically cheapest cloud source to add, if customer demand justified it - but note research question 2's data suggesting Dropbox is not where customers' PHOTOS typically live (more a general file-sync tool than a camera-roll backup target for most consumers).
