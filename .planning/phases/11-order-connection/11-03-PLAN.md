# Plan 11-03 — Load Order in Template Engine

## Objective
Staff enters an order number in template-engine.html → engine calls `getOrderAssets` → pre-configures page count and FP selections, pre-populates FP text panels from structured `fpTexts`, fetches photos from GCS signed URLs, runs EXIF sort, and auto-assembles the book.

## Context
- @pages/template-engine.html — full engine; processOneFile(), buildBookSequence(), renderBook(), window.specialPhotos all exist
- `getOrderAssets` Cloud Function (Plan 11-02) must be deployed and tested first
- GCS signed URLs expire after 1 hour — sufficient for a staff session

## Pre-requisite
Plan 11-02 complete. `getOrderAssets` returns `{ order, files }` for a real order.

## Task 1 — "Load order" UI panel

Add a collapsible panel at the very top of the engine page, above the config bar. Collapsed by default (shows "Load order ▾"). On expand:

```
Order number: [ AEV-___  ] [ Load ]
```

- Style: muted background matching the config bar
- On Load click: call `loadOrder(orderNumber.trim().toUpperCase())`
- Show inline status below the input:
  - `"Loading…"` while in flight
  - `"AEV-001 loaded — Kseniia M, 40 pages, 2 add-ons"` on success
  - Clear error message on failure
- Panel collapses after successful load (staff can re-expand manually)

## Task 2 — `loadOrder()` function

```js
async function loadOrder(orderNumber) {
  // 1. POST to getOrderAssets
  const resp = await fetch('https://europe-west1-aevia-uploads.cloudfunctions.net/getOrderAssets', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ orderNumber }),
  });
  if (!resp.ok) { showLoadError('Order not found'); return; }
  const { order, files } = await resp.json();

  // 2. Apply page count
  //    Find the page count chip matching order.pageCount, click it (triggers existing chip logic)

  // 3. Apply FP selections
  //    order.fpSelections is an array of slugs e.g. ['fp1', 'fp3']
  //    For each slug: find matching FP checkbox in config bar, check it, trigger its change handler
  //    This calls buildBookSequence() + renderBook() automatically

  // 4. Pre-populate FP text panels from order.fpTexts
  //    fpTexts structure: { fp2: ['word1','word2'], fp3: 'my text', fp5: ['left','right'] }
  //    For each key in fpTexts:
  //      - Find the FP spread in window.bookSequence by spreadId === key.toUpperCase()
  //      - Set window.bookCaptions[spreadIndex][side]['textPanel'] = value
  //      - Update the visible contenteditable DOM element
  //    Handle both string (fp3, fp4) and array (fp2 words, fp5 captions) values.
  //    fp2: join words with newlines (one per line in the text panel)

  // 5. Load photos from GCS
  //    Progress: use the debug log panel for "Loading photo N/total…"
  //    Process files sequentially (parallel HEIC is broken):
  //    - fileType === 'cover'   → load as cover photo (call existing handleCoverFile equivalent)
  //    - fileType === 'main'    → feed through processOneFile() → adds to window.photos pool
  //    - fileType === 'special' → fetch blob → File → processOneFile() for EXIF/orientation →
  //                               assign to window.specialPhotos[addonSlug.toUpperCase()]
  //                               → trigger special photo render for that FP spread

  // 6. After all files: EXIF sort → assignPhotosToSpreads() → re-render all spreads
  // 7. Show success status with summary
}
```

**Photo fetch pattern:**
```js
const resp = await fetch(signedUrl);
const blob = await resp.blob();
const file = new File([blob], fileName, { type: blob.type });
// then pass to existing processOneFile(file) or cover handler
```

## Task 3 — FP text panel pre-population detail

`fpTexts` values by FP type:
- `fp2`: array of strings → join with `\n` → set as text in the FP2 contenteditable textPanel
- `fp3`, `fp4`: plain string → set as text in the FP3/FP4 contenteditable textPanel  
- `fp5`: array `['left caption', 'right caption']` → set each in the FP5 left/right caption slots

After setting text, store in `window.bookCaptions` so PDF export picks it up correctly:
```js
window.bookCaptions[spreadIndex][side]['textPanel'] = value;
```
