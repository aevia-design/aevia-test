# Plan 11-04 — PDF Export Wired to GCS Order Path

## Objective
After a staff member loads an order via Plan 11-03, the "Export PDF" button in the template engine should produce a `book-state.json` whose photo references point to GCS signed URLs (not local blob: URLs), so `scripts/export-pdf.js` can fetch full-resolution originals directly from GCS without requiring manual photo re-upload.

## Context
- @pages/template-engine.html — engine; "Export book state" button already exists, exports `book-state.json` with photo blob URLs
- @scripts/export-pdf.js — reads `book-state.json`, fetches photos, draws PDF
- Plan 11-03 must be complete — `loadOrder()` populates `window.photos` from GCS signed URLs
- GCS signed URLs expire after 1 hour — enough for a single session; warn staff if export is delayed

## Pre-requisite
Plan 11-03 complete and tested.

---

## Task 1 — Store GCS URL alongside blob URL in window.photos

When `loadOrder()` fetches photos from GCS (Plan 11-03), currently each file goes through `processOneFile()` which creates a blob: URL. We need to preserve the original GCS URL.

In `loadOrder()` in template-engine.html, after creating the `File` from the GCS blob, store the signed URL on the photo object:

```js
// After processOneFile(file) adds the photo to window.photos:
const idx = window.photos.length - 1;
window.photos[idx].gcsUrl = signedUrl;  // store original GCS URL
```

For photos uploaded manually (not from GCS load), `gcsUrl` will be `undefined` — that's fine; export falls back to blob-to-base64.

---

## Task 2 — Update book-state export to prefer GCS URL

In the "Export book state" button handler, when building the export JSON:

```js
// Current (blob: URL or base64):
photoUrl = window.photos[idx].url;

// Updated (prefer GCS URL if available):
photoUrl = window.photos[idx].gcsUrl || window.photos[idx].url;
```

If any photos use blob: URLs (manually uploaded), show a one-line warning banner in the engine:
```
⚠ Some photos are from local uploads — they will be embedded as base64 in the export (larger file).
```

---

## Task 3 — Update export-pdf.js to fetch GCS URLs

`export-pdf.js` already fetches photos from URLs in `book-state.json`. Verify it handles `https://` URLs (GCS signed URLs) correctly using Node's `fetch` or `https.get`.

If not already handled, add:
```js
async function fetchPhoto(urlOrDataUrl) {
  if (urlOrDataUrl.startsWith('data:')) {
    // base64 data URL — decode directly
    const base64 = urlOrDataUrl.split(',')[1];
    return Buffer.from(base64, 'base64');
  } else {
    // https:// URL (GCS signed URL)
    const resp = await fetch(urlOrDataUrl);
    if (!resp.ok) throw new Error(`Photo fetch failed: ${resp.status} ${urlOrDataUrl}`);
    return Buffer.from(await resp.arrayBuffer());
  }
}
```

Replace any existing photo-load logic with calls to `fetchPhoto()`.

---

## Task 4 — Warn on URL expiry

In the engine, when the order is loaded successfully (Task 1 in 11-03), record the load timestamp:
```js
window._orderLoadedAt = Date.now();
```

When the export button is clicked, check if more than 50 minutes have elapsed (URLs expire at 60min):
```js
if (window._orderLoadedAt && Date.now() - window._orderLoadedAt > 50 * 60 * 1000) {
  alert('⚠ Signed URLs may have expired (loaded over 50 min ago). Reload the order before exporting.');
  return;
}
```
