# Plan 13-02 — Engine + PDF Code Hygiene Pass

## Objective
Tighten the template engine and PDF export code while we're already touching them for Phases 13-01 (bleed SVGs) and 14-01 (caption coordinates). All findings from an independent code review on 2026-05-26 (see `sessions/2026-05-26.md`) are captured here.

## When to run
**After** Plans 13-01 and 14-01 are implemented and verified. Both of those phases edit the same files (`pages/template-engine.html`, `scripts/export-pdf.js`, `assets/Template_Scribble/scribble-data.js`), so it's cheaper to do the hygiene pass once those land than to fix and re-fix.

## Why this matters
The reviewer flagged three categories of risk:
1. **Engine ↔ PDF drift** — same visual property computed differently in the two files. This bug class has bitten us 5+ times already (pt-vs-px caption sizing, spine rotation direction, weight-500 fallback, FP5 array-vs-string, cover caption colour).
2. **Silent fallback paths** — wrong inputs produce wrong output instead of an error, so we discover problems in print rather than at the engine.
3. **Maintainability debt** — dead code, magic numbers, constants in two places. Will slow future work, especially when adding a second template.

## Architecture constants (do not change)
- `SCALE = 3` (px/mm) — engine canvas
- `DPI = 300` — PDF export
- `BLEED_PT = 3mm` in PDF points — photo and caption offset
- No frameworks, no build step. "Shared helper" means a plain `.js` file loaded via `<script>`.

## Task 1 — Quick wins (~15 min)

These are safe to do anytime, even before Phases 13/14 land. Pull forward if there's a free moment.

### 1a. Extract `resolveColor()` to a module-level helper
**Where:** `scripts/export-pdf.js` lines ~301-304 (in `drawCaptions`) and ~549-553 (in `drawCoverCaptions`).
**Problem:** Same hex-or-named-colour lookup is implemented twice. If we add a new colour format (e.g. `rgb()` or `hsl()`) we'll fix one and forget the other, and the PDF will silently fall back to near-black.
**Fix:** Move the function to the top of the file, after the other helpers (~line 80). Both callers reference it.

### 1b. Delete dead code in `pages/template-engine.html`
**Where:** `initAddonFields()` and `initSpecialPhotoZones()` functions — confirm via grep that nothing in the engine still calls them. (Note: these names also exist in `pages/order.html`. The order.html copies are out of scope here; only delete the engine copies if they exist.)
**Problem:** ~150 lines of dead weight. Future-us will read them and waste time understanding code that doesn't run.
**Fix:** Delete. Git history preserves them if we ever need to revive.

### 1c. Add schema/version comments at 4 flagged spots
Document the implicit contracts so future edits don't break them silently.

- `scripts/export-pdf.js:140` (FP5 photo handling) — add comment: `// specialPhotos.FP5 must be array [leftName, rightName]. Legacy string fallback below handles old book-state.json from before 2026-05. Re-export from engine to upgrade.`
- `scripts/export-pdf.js:410` (textPanel style override) — add comment: `// ov shape: { font?, weight? (numeric, e.g. 500), italic? (bool), color?, sizePt?, letterSpacing?, lineSpacing? }. Weight must be numeric — string style names will fall through to 'regular'.`
- `scripts/export-pdf.js:64` (constants block) — add comment: `// SCALE=3 px/mm lives in pages/template-engine.html only. DPI=300 is the print target. If either changes, update both files and re-verify caption sizing math (sizePt * SCALE * 25.4 / 72).`
- `scripts/export-pdf.js:614` (magic 0.75) — add comment: `// 0.75 ≈ cap-height ratio for typical serif fonts (NT Somic, EB Garamond). Used to convert font sizePt to vertical baseline offset.`

## Task 2 — Lock down the caption override schema

**Where:** `pages/template-engine.html` (toolbar save path, lines ~1599-1600 and the `spreadCaptionStyles` / `coverCaptionStyles` assignment sites) + `scripts/export-pdf.js` (every `ov.weight` / `ov.italic` read site).

**Problem:** The PDF assumes `ov.weight` is numeric (`>=700 → bold`, `>=600 → semibold`, `>=500 → medium`, else `italic ? 'italic' : 'regular'`). If the engine ever saves a string style name (`ov.style: 'medium'`) instead of numeric weight, the PDF silently falls through to 'regular'. We hit this exact bug on 2026-05-26 — see session log.

**Fix:**
1. Audit every place in `template-engine.html` that writes to `spreadCaptionStyles[si][side][slotIdx]`, `coverCaptionStyles`, or any caption override object. Confirm `weight` is always written as a number (not string), `italic` as a boolean.
2. In `export-pdf.js`, add a guard at the top of the weight-resolution branches: if `ov.weight` is a string or undefined and any other style hint exists, log `console.warn('caption override schema mismatch:', ov)` so future drift is visible at export time.
3. Document the schema in a comment at the toolbar save site.

**Verify:** edit one caption to each of Regular / Medium / Semi-Bold / Bold / Italic in the engine, export to PDF, open both side-by-side, confirm visual match.

## Task 3 — Add a version field to `book-state.json`

**Where:** `pages/template-engine.html` (book-state export) + `scripts/export-pdf.js` (book-state import).

**Problem:** Schema has evolved several times (cover captions added; FP5 changed string → array). Old book-state files silently work via legacy fallbacks. No way to tell at a glance whether a file is current.

**Fix:**
1. Engine writes `{ schemaVersion: 2, ... }` (bump to whatever the next number is) at the top of book-state.json.
2. Export script reads `schemaVersion` and logs a warning if missing or older than current. Keep the legacy fallbacks — don't fail hard, just be loud.
3. Document what changed in each version in a comment in export-pdf.js.

## Task 4 — Harden `stripHtml()` against future caption HTML

**Where:** `scripts/export-pdf.js:318` (and the helper at lines ~23-31).

**Problem:** `stripHtml()` only strips tags by name (`<b>`, `<i>`, etc.). If the engine ever saves a `<span style="...">` (e.g. via execCommand or a future formatting toolbar), the regex won't strip it and the PDF will render the raw text without formatting — silent drift.

**Fix:** After stripping, compare the result against `text.replace(/<[^>]+>/g, '')`. If they differ, `console.warn` the unhandled HTML so we catch new tag types at export time. Don't change the strip behaviour itself — just make the difference visible.

## Task 5 — Loud fallback in `resolveVariant()`

**Where:** `pages/template-engine.html` lines ~2307-2311.

**Problem:** If `scribble-data.js` has a typo (e.g. variant key `'Horizontal'` instead of `'H'`), `resolveVariant()` silently picks the first available key. The engine renders something — just not the right thing — and we don't notice until print.

**Fix:** Add `console.warn('resolveVariant: requested', orientationKey, 'not found for spread', spreadId, '— falling back to:', fallbackKey)`. Don't change behaviour, just make it visible in the console.
