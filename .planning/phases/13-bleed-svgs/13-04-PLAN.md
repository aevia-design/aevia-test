# Plan 13-04 — PDF Export: Bleed SVGs + Coordinate-Based Captions

## Status
⬜ todo

## Prerequisite
**Plan 13-01 must be verified first.** This plan consumes the new `scribble-data.js` / `book-state.json`
shape (slots with `xBleed`/`yBleed`; captions with `xMm`/`yMm`/`wMm`/`hMm`/`halign`/`valign`).

---

## Objective
Update `scripts/export-pdf.js` to:
1. Place SVGs at page origin (0,0) — they now include 3mm bleed and should fill the full bleed page
2. Use `xBleed`/`yBleed` for photo slot placement (coordinates already include bleed)
3. Place captions using explicit `xMm`/`yMm`/`wMm`/`hMm` (replacing position+offset calculation)
4. Remove all `position`-based caption rendering code

---

## Architecture constants
- `BLEED_MM = 3` (mm) → `BLEED_PT = 3 * 72/25.4 ≈ 8.504 pt`
- `PAGE_SIZE_MM = 200` → `PAGE_SIZE_PT ≈ 566.93 pt`
- `PAGE_WITH_BLEED_MM = 206` → `PAGE_WITH_BLEED_PT ≈ 583.94 pt`
- `MM_TO_PT = 72 / 25.4 ≈ 2.835`
- Photo/caption coordinates from `scribble-data.js` in mm → multiply by `MM_TO_PT` for pdf-lib

---

## Task 1 — SVG placement: origin instead of BLEED_PT offset

Find `drawSvg` calls in `renderPage()` (spreads) and `renderCoverImage()` (cover).

Currently placed at `(BLEED_PT, BLEED_PT)` offset (to skip the bleed area since old SVGs had no bleed).

Change to origin placement with bleed dimensions:

```js
// Before (content-area SVG)
page.drawSvg(svgContent, {
  x: BLEED_PT, y: BLEED_PT,
  width: PAGE_SIZE_PT, height: PAGE_SIZE_PT
});

// After (bleed SVG)
page.drawSvg(svgContent, {
  x: 0, y: 0,
  width: PAGE_WITH_BLEED_PT, height: PAGE_WITH_BLEED_PT
});
```

Where `PAGE_WITH_BLEED_PT = 206 * MM_TO_PT`.

Note: pdf-lib places (x=0, y=0) at the **bottom-left** of the page. The svg content should cover 0..PAGE_WITH_BLEED_PT in both axes. Verify the SVG renders right-way-up and fills to the edges.

---

## Task 2 — Photo slot placement: use xBleed/yBleed

In `renderPage()`, photo slots are placed using coordinates from `book-state.json`.
The book-state's slot definitions come from `scribble-data.js` which now has both `x`/`y` (no bleed)
and `xBleed`/`yBleed` (with bleed).

For PDF, use **with-bleed** coordinates since the PDF page includes bleed:

```js
// Before
const slotXPt = slotDef.x * MM_TO_PT + BLEED_PT;
const slotYPt = slotDef.y * MM_TO_PT + BLEED_PT;

// After
const slotXPt = slotDef.xBleed * MM_TO_PT;
const slotYPt = slotDef.yBleed * MM_TO_PT;
```

Remove the `+ BLEED_PT` addition — bleed is already baked into the coords.

**Check all slot-rendering code paths**: regular spreads, FP spreads with special pools, the cover slot.

## Task 3 — Caption placement: switch to coordinate-based

This is the largest change. Find `drawCaptions()` (spreads) and `drawCoverCaptions()` (cover).

### 3a. Spread captions

Currently `drawCaptions()` calculates text box position from `capDef.position`, `capDef.offset`,
and the slot's photo bounds. Replace with:

```js
// capDef.xMm / capDef.yMm are already with-bleed coords
const textX = capDef.xMm * MM_TO_PT;
const textY = pageHeightPt - (capDef.yMm * MM_TO_PT) - (capDef.hMm * MM_TO_PT);
// (pdf-lib y is from bottom; subtract yMm and box height from page height)
const boxWidthPt  = capDef.wMm * MM_TO_PT;
const boxHeightPt = capDef.hMm * MM_TO_PT;
```

Use `capDef.halign` for text alignment:
- `'center'` → `TextAlignment.Center`
- `'left'` → `TextAlignment.Left`
- `'right'` → `TextAlignment.Right`

`capDef.valign` affects which y anchor to use within the box:
- `'top'` → start drawing from `textY + boxHeightPt` downward (pdf-lib baseline)
- `'center'` → offset by `(boxHeightPt - totalTextHeight) / 2`
- `'bottom'` → offset by `boxHeightPt - totalTextHeight`

Keep `wrapText()` — it now uses `boxWidthPt` directly instead of inferring from slot + offset.

### 3b. Cover captions

`drawCoverCaptions()` already uses `cap.xMm`/`cap.yMm` from the cover section of `scribble-data.js`.
Cover CSV coords are "with bleed" (18mm bleed). No offset additions needed:

```js
// Before (cover already used xMm/yMm but may have added bleed offset)
const x = (cap.xMm + COVER_BLEED_MM) * MM_TO_PT;  // if this existed, remove it

// After
const x = cap.xMm * MM_TO_PT;  // already with bleed
```

Verify spine captions still rotate correctly (`rotate: 270` → `angle: 90` in pdf-lib).

### 3c. Remove old position-based calculation

Delete the switch/if-else block that handled `capDef.position` values (`'below'`, `'upper-right'`,
`'lower-right'`, `'above'`, `'center'`, `'lower-right'`). The `wrapText()` helper is still needed —
keep it, just remove the callers that used position+offset to compute the box.

## Watch-outs

- pdf-lib uses **bottom-left** as (0,0). When converting mm to pt: `y_pdf = pageHeightPt - y_mm * MM_TO_PT - boxHeight_pt`. The y-axis flip is the most common source of caption-position errors.
- `xMm`/`yMm` in `scribble-data.js` are **with bleed** — no `+ BLEED_PT` addition needed. If you add BLEED_PT on top, captions shift down-right by 3mm.
- Slot coords: use `xBleed`/`yBleed`, NOT `x`/`y`. The `x`/`y` (no-bleed) are for the engine only.
- Cover bleed is 18mm (not 3mm). The cover CSV coords already include 18mm. Don't mix bleed values between cover and spreads.
- `wrapText()` width argument is now `capDef.wMm * MM_TO_PT` directly. Old code may have been computing it as `(pageWidthMm - capDef.xMm - rightMarginMm) * MM_TO_PT`. Replace entirely.
