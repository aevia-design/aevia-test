## Objective
Update `pages/template-engine.html` to:
1. Render bleed SVGs correctly (offset −3mm so only content area is visible)
2. Place captions using explicit box coordinates from `scribble-data.js` (replacing position+offset calculation)
3. Keep slot photo placement unchanged (already uses `x`/`y` no-bleed coords × SCALE)

---

## Architecture constants
- `SCALE = 3` (px/mm)
- `BLEED_MM = 3` (mm) — spread bleed. Cover bleed is different (18mm) — see Task 3.
- Content canvas: 600×600px (200mm × 3)
- SVG with bleed: 618×618px (206mm × 3) — offset −9px to show only content area

---

## Task 1 — SVG overlay: offset by −bleed for spreads

Find where spread SVG overlay `<img>` elements are sized and positioned in `renderSpread()`.
Currently sized to 600×600 and positioned at top:0, left:0.

Change to:
```js
svgImg.style.width  = (SCALE * (CONTENT_MM + BLEED_MM * 2)) + 'px';  // 618px
svgImg.style.height = (SCALE * (CONTENT_MM + BLEED_MM * 2)) + 'px';  // 618px
svgImg.style.top    = (-BLEED_MM * SCALE) + 'px';   // -9px
svgImg.style.left   = (-BLEED_MM * SCALE) + 'px';   // -9px
```

Where `CONTENT_MM = 200`, `BLEED_MM = 3`. Use the existing `SCALE` constant.

The spread canvas container already has `overflow: hidden` — this clips the bleed region naturally.

**Verify:** Load a spread — the SVG artwork aligns with photo slot boundaries. No artwork clipped inside the content area. Bleed not visible.

## Task 2 — Caption rendering: switch to coordinate-based placement

This is the largest change. Remove the old `position`+`offset`-based calculation and replace
with explicit box dimensions from `capDef`.

### 2a. Find the caption rendering code

In `renderSpread()`, find where caption `contenteditable` overlays are positioned.
Currently the code reads `capDef.position` (e.g. `'below'`, `'upper-right'`, `'center'`)
and computes `left`/`top` from the slot coordinates + offset.

### 2b. Replace with coordinate-based placement

New logic for any caption with `capDef.allowed && capDef.xMm !== undefined`:

```js
// Convert from with-bleed mm to canvas px (subtract bleed, multiply by SCALE)
const capLeft   = (capDef.xMm - BLEED_MM) * SCALE;
const capTop    = (capDef.yMm - BLEED_MM) * SCALE;
const capWidth  = capDef.wMm * SCALE;
const capHeight = capDef.hMm * SCALE;

captionEl.style.left      = capLeft   + 'px';
captionEl.style.top       = capTop    + 'px';
captionEl.style.width     = capWidth  + 'px';
captionEl.style.height    = capHeight + 'px';
captionEl.style.textAlign = capDef.halign || 'left';
// valign: apply via flexbox or paddingTop as needed
```

### 2c. Handle valign

`capDef.valign` values from the CSV: `'top'`, `'center'`, `'bottom'`.

Apply via CSS on the caption element:
```js
captionEl.style.display        = 'flex';
captionEl.style.flexDirection  = 'column';
captionEl.style.justifyContent =
  capDef.valign === 'center' ? 'center' :
  capDef.valign === 'bottom' ? 'flex-end' : 'flex-start';
```

### 2d. Remove all old position-based calculation

Delete the switch/if-else block that computed caption position from `capDef.position` values
(`'below'`, `'upper-right'`, `'lower-right'`, `'above'`, `'center'`). This code path is fully replaced.

**Do not remove** the `capDef.allowed` check — still needed.

### 2e. Update toolbar AI button positioning

The AI caption button is positioned relative to the caption box. After this change, use:
```js
aiBtn.style.left = capLeft + 'px';
aiBtn.style.top  = (capTop - 22) + 'px';  // 22px above the caption box
```

## Watch-outs

- Caption coords in scribble-data.js are **with bleed** — always subtract `BLEED_MM` before multiplying by SCALE. If you forget, captions will appear shifted right/down by 9px (3mm × 3).
- Photo slot coords are **without bleed** — use `x`/`y` directly × SCALE. Do NOT use `xBleed`/`yBleed` in the engine.
- Old position-based caption code may have an `offset` fallback used in other places (e.g. the AI button, the PDF). Check for all reads of `capDef.position` and `capDef.offset` — none should remain after this plan.
- The `upper-right` caption position had a special `text-align: left` override in the old code. The new `halign` field from the CSV handles alignment directly — no special-case overrides needed.
