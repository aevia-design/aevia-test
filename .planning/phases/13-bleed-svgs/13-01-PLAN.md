# Plan 13-01 — Bleed SVG Migration

## Objective
Kseniia will re-export all spread SVGs with 3mm bleed included (206×206mm instead of 200×200mm). Update the template engine and PDF export script to handle bleed SVGs correctly:
- **Engine preview:** show only the 200×200mm content area (no bleed visible to staff)
- **PDF export:** SVG starts at page origin (0,0), covers the full 206×206mm bleed page

## ⚠ Prerequisite
Kseniia delivers the re-exported SVGs. Do not start this plan until the new SVG files are in `assets/Template_Scribble/Spreads/`.

## Why this matters
Printing machines are not 100% precise — they may cut 1–3mm from the intended edge. Graphic elements that extend into the bleed zone prevent a white edge appearing if the cut is slightly off. Without bleed on the SVG, there's a risk of a thin white strip on the printed edge.

## Architecture constants (do not change)
- `SCALE = 3` (px/mm): 200mm content = 600px canvas
- Bleed = 3mm each side → SVG is 206×206mm = 618×618px at SCALE=3
- Slot coordinates in `scribble-data.js` are always in content-area mm (0–200mm) — **do not change them**
- `BLEED_PT` in export-pdf.js = 3mm in PDF points — used for photo/caption placement, still correct

## Task 2 — Template engine: offset SVG overlay by −bleed

In `template-engine.html`, the SVG overlay is rendered as an `<img>` (or similar) positioned over the spread canvas. Currently it's sized to fit the 600×600 canvas exactly.

With bleed SVGs, the SVG is 618×618px. We need to:
1. Size the SVG image to 618×618px
2. Offset it by −9px top and −9px left (= 3mm × 3px/mm) so the content area aligns with the 600×600 canvas
3. Add `overflow: hidden` on the canvas container (already present) to clip the bleed border

```css
/* Before (content-area SVG) */
.svg-overlay { width: 600px; height: 600px; position: absolute; top: 0; left: 0; }

/* After (bleed SVG) */
.svg-overlay { width: 618px; height: 618px; position: absolute; top: -9px; left: -9px; }
```

Do this for all SVG overlay elements in the engine — spreads and any cover SVG if applicable.

Read the current SVG rendering code in template-engine.html before editing to find the exact element and style approach used.

---

## Task 3 — PDF export: place SVG at page origin

In `scripts/export-pdf.js`, the SVG is currently placed at an offset of `BLEED_PT` (3mm in PDF points) to align it with the content area inside the bleed page. With bleed SVGs, the SVG should start at (0, 0).

Find the SVG placement code in `renderPage()` and `renderCoverImage()`:
```js
// Before (content-area SVG, offset needed)
page.drawSvg(svgContent, { x: BLEED_PT, y: BLEED_PT, width: PAGE_SIZE_PT, height: PAGE_SIZE_PT });

// After (bleed SVG, no offset needed)
page.drawSvg(svgContent, { x: 0, y: 0, width: PAGE_SIZE_WITH_BLEED_PT, height: PAGE_SIZE_WITH_BLEED_PT });
```

Where:
- `PAGE_SIZE_PT` = 200mm in PDF points ≈ 566.93pt
- `PAGE_SIZE_WITH_BLEED_PT` = 206mm in PDF points ≈ 583.94pt

Photos and captions keep their `BLEED_PT` offset — unchanged.

Read the current export-pdf.js SVG drawing code before editing to confirm exact variable names and approach.
