# Plan 13-01 — CSV Parser Rewrite + scribble-data.js Format Update

## Status
⬜ todo

## Objective
Both CSV files have been updated by Kseniia with new column structures. SVGs now include 3mm bleed.
This plan rewrites `csv-to-template.js` to parse the new formats and outputs an updated `scribble-data.js`
with the new data shape that Plans 13-03 (engine) and 13-04 (PDF) will consume.

**Do Plans 13-03 and 13-04 after this plan is verified** — they depend on the new scribble-data.js shape.

---

## What changed in the CSV files

### Scribble_sizing_full.csv (spreads)
- **Delimiter changed: now comma, not semicolon**
- **Line 0 is a title row** (`Scribble_sizing_full`) — line 1 is the headers, line 2+ are data
- Duplicate column names at indices 7–8 and 13–16 (same names as 5–6 and 9–10) — must parse by index
- Slot coordinates: 4 x/y columns instead of 2:
  - col 5–6: `X/Y (mm) - without bleed` → `slot.x`, `slot.y` (engine preview)
  - col 7–8: `X/Y (mm) - with bleed` → `slot.xBleed`, `slot.yBleed` (PDF)
- Caption box: **new explicit coordinates** replacing `captions_position` text (col 12):
  - col 13–14: `X/Y (mm) - with bleed` → `cap.xMm`, `cap.yMm`
  - col 15–16: `Width/Height (mm)` → `cap.wMm`, `cap.hMm`
  - col 17: `captions_Halignment` → `cap.halign`
  - col 18: `captions_Valignment` → `cap.valign`
- `captions_position` (col 12) is **legacy — do not read or emit it**

### Scribble_Template_Sizing_Cover.csv (cover)
- Still semicolon-delimited, no title row — unchanged from before
- Photo coordinate columns renamed:
  - Old: `Photo_X (mm)`, `Photo_Y (mm)`, `Photo_Width (mm)`, `Photo_Height (mm)`
  - New: `photo_Xmm_without bleed`, `photo_Ymm_without bleed`, `photo_Xmm_with bleed`,
    `photo_Ymm_with bleed`, `photo_Width_mm`, `photo_Height_mm`
- Caption coordinate columns renamed + both bleed variants added:
  - Old: `Captions_1_X (mm)`, `Captions_1_Y (mm)`
  - New: `captions1_Xmm_without bleed`, `captions1_Ymm_without bleed`,
    `captions1_Xmm_with bleed`, `captions1_Ymm_with bleed`  
  - Same pattern for captions2
- New: `Captions_1_direction`, `Captions_2_direction` — replaces hardcoded `rotate: 270` for spine
  - Value: `"Rotate all text 270 degree"` → emit `rotate: 270` in output
  - Value: `"horisontal"` → omit rotate field
- `Captions_1_fontColor` / `Captions_2_fontColor` may or may not be present — read gracefully

## Column index reference (spread CSV, 0-based)

Parse by index for cols 5–16 to avoid duplicate-name confusion:

| Index | Name | Output field |
|-------|------|-------------|
| 5 | X (mm) - without bleed | `slot.x` |
| 6 | Y (mm) - without bleed | `slot.y` |
| 7 | X (mm) - with bleed | `slot.xBleed` |
| 8 | Y (mm) - with bleed | `slot.yBleed` |
| 9 | Width (mm) | `slot.w` |
| 10 | Height (mm) | `slot.h` |
| 11 | captions allowed | (bool check) |
| 12 | captions_position | **IGNORE** |
| 13 | X (mm) - with bleed | `cap.xMm` |
| 14 | Y (mm) - with bleed | `cap.yMm` |
| 15 | Width (mm) | `cap.wMm` |
| 16 | Height (mm) | `cap.hMm` |
| 17 | captions_Halignment | `cap.halign` |
| 18 | captions_Valignment | `cap.valign` |

Cols 19–26 can still be accessed by name — no duplicates there.

## Task 1 — Fix spread CSV parser

In `csv-to-template.js`:

1. Change delimiter from `';'` to `','` for spread CSV
2. Skip title row: headers = `rawLines[1]`, data = `rawLines.slice(2)`
3. Build a parallel index-based row parser (alongside name-based) to read cols 5–16 reliably
4. Update `buildSlot()`:
   - Read `x`, `y` from col 5, 6 (no bleed)
   - Read `xBleed`, `yBleed` from col 7, 8 (with bleed)
   - Emit both on slot object
5. Update `parseCaption()` / `buildSlot()`:
   - If `captions allowed === 'yes'`:
     - Read `xMm` from col 13, `yMm` from col 14, `wMm` from col 15, `hMm` from col 16
     - Read `halign` from col 17, `valign` from col 18
     - Read typography from cols 19–26 (unchanged column names)
     - **Do not read `captions_position` (col 12)**
   - If `captions allowed !== 'yes'`: emit `{ allowed: false }`
6. Remove `parseCaptionStyle()` dependency on `captions_alignment` (old single-column) —
   alignment is now `halign`/`valign` from cols 17–18

   (column may or may not exist — no change to existing logic needed)

## Task 3 — Update scribble-data.js output format

Update `serializeSlot()`:

```js
// Before
{ slot: 1, x: 105, y: 70, w: 150, h: 100, ... }

// After
{ slot: 1, x: 105, y: 70, xBleed: 108, yBleed: 73, w: 150, h: 100, ... }
```

Update `serializeCaption()`:

```js
// Before (position-based)
{ allowed: true, position: 'below', offset: 50, font: 'NT Somic', sizePt: 14, ... }

// After (coordinate-based)
{ allowed: true, xMm: 108, yMm: 179.5, wMm: 100, hMm: 13,
  halign: 'center', valign: 'top', font: 'NT Somic', sizePt: 14, ... }
```

**Remove** `position` and `offset` fields from caption output entirely.

Update `serializeCover()` to emit `xMm`/`yMm` from "with bleed" coords (already stored as such in `parseCoverCsv`).

## Watch-outs

- The spread CSV title row (`Scribble_sizing_full`) on line 0 must be skipped — if the parser reads it as a header row, all columns will be undefined
- Caption box coords in the spread CSV are **with bleed** (like the cover). For the engine preview, the rendering code (Plan 13-03) will subtract bleed: `(xMm - BLEED_MM) * SCALE`. Do not subtract bleed here in the CSV parser — keep the raw values.
- `captions_position` stays in the CSV as a human-readable reference for Kseniia. The parser should silently ignore col 12 — do not warn or error on it.
- FP text panel rows (Page = '-') have no slot or caption box coords — the text panel caption uses `xMm/yMm/wMm/hMm` from cols 13–16. Check that these are populated correctly for FP1 (Birthday wishes) and FP2 (Funny words).
